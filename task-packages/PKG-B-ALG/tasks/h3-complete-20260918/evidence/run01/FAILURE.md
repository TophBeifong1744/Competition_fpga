# run01 首次失败记录

结论：首次合成宽带向量的通道移位符号写反，导致预期 `+X/0°` 的输入被整数链解释为约 `-X/-180°`，跟踪器未进入预期锁定状态。本记录保留开发首错；不得把 run01 当当前 golden。

- 症状：TDOA 符号与 `config.json` 的“阵列指向声源”方向约定相反。
- 根因：`run_golden.py` 构造 mic1/mic2 时采用了反向切片，等价于把应当较晚到达的通道写成提前到达。
- 修复：仅纠正合成测试向量的切片方向；未修改 PHAT、DOA、Tracker、DAS 算法及其阈值。
- 复测：`evidence/run02/` 首次完成方向修正，当前 `evidence/run03/` 中 `ux_q20=1123531`、`uy_q20=0`、`azimuth_q8_deg=0`，连续五帧后状态为 `LOCKED`；逐级数组检查 0 个码差。
- 限制：该修复只证明测试向量与合同方向一致，不证明真实声学角度精度或 AMD FFT 位精确一致。
