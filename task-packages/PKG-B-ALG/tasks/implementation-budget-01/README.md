## 1. 计算节拍与每帧操作

固定六路 48 kHz，帧长 1024、步进 512，93.75 帧/秒；采满第一帧 21.333 ms，后续每 10.667 ms 更新一次。300–4000 Hz 对应 513 个实 FFT 频点中的 7～85，即 79 个频点。

| 当前源码操作 | 每帧数量或上界 | 说明 |
|---|---:|---|
| Hann 加窗 | 6144 次实数乘法 | 六路各 1024 点 |
| 1024 点实 FFT | 6 次 | NumPy 一次批量调用处理六向量，不能计为一次变换 |
| 麦克风对互谱 | 7695 次复数乘法 | 15×513；朴素实现约 30780 实乘、15390 实加 |
| 复数模 | 7695 次 | 数学上可用平方、求和、开方；NumPy/IP 的实际实现另定 |
| 幅值归一化 | 最多 7695 次复数除实数 | 通过频点数门槛的 pair 才执行；相当于每复数两个分量归一化，实际 reciprocal/divider 方案未定 |
| 1024 点实 IFFT | 0～15 次 | 少于 12 个保留频点的 pair 不做 IFFT，预算按 15 |
| 物理时延窗口峰值候选 | 合计 207 个位置 | 12 个 pair 各 13 点、3 个各 17 点；不是搜索全部 1024 点 |
| 三点抛物线峰值修正 | 最多 15 次 | 含分母保护、除法和 ±0.5 裁剪 |
| 几何秩检查 | 最多 2 次 | 当前 localize 包装与 baseline 各检查一次，不能漏算 |
| 最小二乘 | 最多 1 次 | 有效 pair 数×3，最多 15×3；随后向量范数、残差和有效性判断 |

当前互谱与幅值归一化在完整 513 点上计算，不能因为有效带只有 79 点就把软件成本写成 15×79。将其改为频带稀疏实现是后续优化，不是当前事实。

FFT/IFFT 总上界为每秒 **1968.75 次 1024 点变换**，即 2,016,000 个等效完整变换输入点/秒。完整复数 radix-2 的粗参照为每帧 107520 个蝶形，但实 FFT 可使用不同算法；这不是当前 NumPy 的精确 FLOP，也不是 FPGA 实测周期。

若仅作排期示例，假设一个支持连续输入的 FFT 引擎每拍接一完整变换点、时钟 100 MHz，则数据输入阶段下界为每帧 21504 拍（215.04 µs）。这不是实际变换总延迟或占用率：还需计入 IP 首尾延迟、变换间隙、正反切换、输出重排、仲裁和其他计算。100 MHz 仅为算例，不是已确认工程时钟。

跟踪每帧另有归一化、方向夹角与锥边界判断；捕获最多比较之前 4 个候选，锁定后比较当前方向与上一方向。当前浮点代码使用范数/acos，显示还涉及方向角；如拟改为点积阈值或 PS 显示计算，需单独验证边界行为，不能擅改默认实现。

## 2. 音频计算不能只算静态 DAS

静态方向最多 12 个非零 tap（每麦两个），每输出点最多 12 次乘加。当前动态音频同时计算 ramp_from 与 goal，再混合；即使过渡完成、alpha=1，源码仍会计算旧滤波器。

- 新目标权重最多 12 个非零 tap；过渡被反复打断时，旧混合权重保守上界为 6×9=54 个。
- 因而当前滤波部分保守上界为每输出点 **66 次乘加**，即 **3.168 M MAC/s**，另有每点两次混合乘法及一次加法。
- 每个音频子块还有 108 个权重非零检查；HOLD 在块内到期可把一个输入块拆成两个子块。另有 alpha 计算/除法、权重更新、方向转延时等开销，上述 MAC 不包括它们。
- 稳态跳过无用旧滤波器、把稀疏 tap 实现为硬件数据通路属于后续优化，尚未实施。

实际教学程序还逐帧保存事件、字符串模式和 JSON，不能将滤波 MAC 换算成该 Python 程序的全部时间。

## 3. 缓存与搬运

下表是显式缓存规划：假设环形帧缓存与 DMA 新块双缓冲分开分配，pair 顺序处理并复用工作区。不是测得的 Python 峰值内存，也不是已综合 BRAM。

| 缓存项 | 当前 float64/complex128 对应字节 | 32 位实分量示例字节 |
|---|---:|---:|
| 六路 1024 点帧环形区 | 49152 | 24576 |
| 六路 512 点新块双缓冲 | 49152 | 24576 |
| 六路 513 点频谱 | 49248 | 24624 |
| 一个 pair 互谱及归一化谱 | 16416 | 8208 |
| pair 幅值＋mask＋相关序列＋15 个时延 | 12929 | 6721 |
| Hann | 8192 | 4096 |
| 音频 8×6 历史 | 384 | 192 |
| 四组 6×9 音频权重 | 1728 | 864 |
| 单声道 512 点输出双缓冲 | 8192 | 4096 |
| **合计** | **195393（190.8 KiB）** | **97953（95.7 KiB）** |

32 位分量列是存储方案示例，不是已冻结的定点格式；例如保留未缩放 FFT 的 34 位结果就不能直接套这列。还缺 FFT IP 内部 RAM、对齐、缓存一致性、描述符、AXI FIFO、NumPy 临时数组与日志；缓存能否复用、需多少端口由 A 排程决定。

当前 offline execute 会 `list(iter_frames(...))` 保存全部帧副本：0.96 秒输入仅帧数组就约 4.17 MiB，约 3 秒输入为 13,811,712 字节（13.17 MiB），另有输入数组、输出/模式列表和记录。这不是可直接搬上板的有界流式存储实现。

| 采样存储 | 六路持续输入 | 单路音频输出 | 定位读取重叠帧 |
|---|---:|---:|---:|
| 24 位紧凑存储 | 864000 B/s | 144000 B/s | 1728000 B/s |
| 32 位容器 | 1152000 B/s | 192000 B/s | 2304000 B/s |
| float64 | 2304000 B/s | 384000 B/s | 4608000 B/s |

帧读取是逻辑读需求，不必全都成为 DDR 流量；它是否与采集、音频共享片上缓存取决于架构。禁止把三列简单相加称为实测 AXI 带宽。PDM 比特率、抽取倍率和中间滤波带宽尚未获得 A 的实际约束。

## 4. 延迟必须分项

- DAS 相对阵列中心信号的公共处理延时：4 点，0.0833 ms；历史预热最多 8 点。
- 当前教学入口首次等待 1024 点，之后按 512 点处理。需在实际调度中计入首帧/块等待；不能宣称端到端只有 0.0833 ms。
- 原跟踪器最快连续五帧捕获：从录音段开始 64 ms；不是最坏捕获上界，噪声下可一直不锁定。未锁定期间已有单麦音频，不需要等锁定才输出。
- 方向/模式过渡：10 ms，是混合持续时间，不是额外缓存积压。
- HOLD：最多 200 ms 证据保持；到期开始 10 ms 淡出，不冒充 fresh，也不是算法计算耗时。
- PDM 抽取群延迟、DMA、操作系统调度、Codec/播放器缓冲和真实计算时间需 A 实测。

observations.json 保存本机每帧定位调用的 P50/P95/最大耗时，仅一次带计数器的运行；不含跟踪、音频、I/O 或硬件。虽本机观察小于 10.667 ms 步进周期，也不能据此判定全链实时通过。

## 5. 定点范围与风险（建议候选，未冻结）

本文用 S(W,F) 表示 W 位有符号数、F 位小数；U(W,F) 表示无符号。以下以入口已经正确缩放到 |x|≤1 为前提。

| 位置 | 候选/增长分析 | 必须验证的风险 |
|---|---|---|
| PCM 输入 | S(24,23) 对应 [-1,1) | 当前合成输入峰值约 4.45，干扰例约 5.31；直接转此格式会削顶。H1 真 PCM 与合成 RMS 信号不能共用未经声明的标度 |
| Hann | U(18,17)，可精确容纳 1 | 窗乘积先扩位，再声明舍入；低能量尾部量化可能改变保留频点 |
| 未缩放 1024 点 FFT | 从 24 位输入保留最多 10 位增长，候选 S(34,23) | 蝶形级缩放或 block-floating 是另一方案，指数需贯穿互谱；32 位存储例不能直接容纳该格式 |
| 复数互谱 | 两个 34×34 的 68 位乘积，求和/差预留 69 位，F=46 | 不应立即截到原位宽；模平方和开方需要额外扩位或归一化方案，成本由 A 选择 |
| PHAT | 归一化后各分量绝对值≤1，可考察 S(25,23) | 原 1e-15 绝对保护无法原样落到常见小数精度；不能未经验证替换成“一 LSB” |
| IFFT | 需声明内部增长、每级缩放及最终 1/1024 | 不能让 IFFT 隐式归一化与软件不同，影响峰形、抛物线分母与阈值 |
| 时延 | 可考察 S(18,12)，范围 [-32,32) | 最大物理界约 7.916 点，但峰修正中间值也要容纳；保留缺失/无效标志，不能用定点 0 替代 NaN |
| 方向与 LS | 暂不冻结 | 有效 pair 集合变化、矩阵秩与条件数变化；一个全 pair 伪逆不能未经验证用于所有缺失模式 |
| DAS 权重 | 非负，可考察 U(24,23)，含 1 | 单麦/过渡系数舍入后权重和不一定等于 1；跨方向更新不能重置音频历史 |
| 音频累加 | 24 位样本×24 位权重先保留 48 位；通用 54 tap 和保守预留 6 位增长 | 54 位累加是保守算术起点，并非最优资源结论；最终舍入、饱和并计溢出，禁止回绕 |

其他必须保留的判决点：2% 幅值掩码、至少 12 个频点、物理 lag 界加 0.05 点、抛物线分母 -1e-15、LS norm 0.7～1.3、残差 0.5 点，以及 30°/8°/20° 方向判断。量化可能改变离散判决，不只改变平均角度。

现有 WAV 共同增益来自看完整段后的峰值归一化，只服务离线试听；实时入口不能依赖未来峰值。实际 PCM 标度、固定增益/削顶规则须在输入契约中明确。
