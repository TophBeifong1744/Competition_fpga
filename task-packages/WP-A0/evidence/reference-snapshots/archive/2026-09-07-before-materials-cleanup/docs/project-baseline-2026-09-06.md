## 3. 已冻结的项目边界

以下内容可以作为团队当前共同约束：

1. V1 先完成固定四麦阵列的“同步采集 → 定位 → 手动/自动指向波束形成 → 音频输出与状态展示”。
2. 四通道必须共用采样时基，并以同一采样序号的四路样本组交接，不能把四条独立流事后假定为同步。
3. 定位、连续音频和后续机械控制使用不同时间尺度；机械路径不得反压音频采集。
4. 音频改善必须用同一组四通道录音比较：固定单麦、手动真实方向、自动估计方向。
5. 40 mm 正方形只是首测候选，最终阵列间距和声学指标由波束图与真实录音共同决定。
6. 转台保留为 M7 扩展；M5 以前只预留接口、空间、供电、坐标和时间戳，不采购执行机构，不把机械转动当作声学性能补丁。
7. 在 M0 未通过前，不实现带猜测接口的 `mic_phy_rx`，也不开始 FFT、GCC-PHAT 或 DOA RTL。

## 4. 尚未冻结的关键事实

| 未决项 | 缺失证据 | 对后续工作的影响 |
|---|---|---|
| 手中 Zynq 板的准确型号与版本 | 核心板、底板、FPGA 芯片、音频 Codec 的清晰丝印照片 | 不能把资料包中的引脚和电平转成正式 XDC |
| ADC、DAC 与麦克风完整型号 | 器件/模块正反面照片、数据手册链接或 PDF、现有数量 | 不能确定 PDM、I2S/TDM 或并行 ADC 路线 |
| 四路采集时钟树 | 外设主从关系、时钟频率、边沿、帧结构 | 不能冻结 `mic_phy_rx` 或 CDC 结构 |
| 四路样本格式 | 有效位宽、存储位宽、补码格式、通道顺序 | 不能冻结接口参数和测试向量格式 |
| Vivado 环境 | 三名成员实际安装版本、目标 part/board | 不能验证可重建工程入口 |
| 原始录音导出路径 | DDR、SD 或网络能力及 PS 环境 | 不能完成 M1 的长录音可重复导出 |
| V1 演示场景 | 房间、距离、角度、目标/干扰电平、时长 | 不能把“5°/4 dB”改写成可验收指标 |

## 5. 基线变更规则

1. 每个工作包使用短分支，命名建议为 `codex/wp-<编号>-<简述>`；一个工作包只设一名负责人。
2. 合入 `main` 前由另一名成员复核，提交说明应写清输入、输出、验证方法和未解决问题。
3. 模型通过、RTL 仿真通过、综合时序通过、板上实测通过分别记录，不互相替代。
4. 参数或接口发生变化时，同时更新接口契约、测试向量、验证结果和使用该参数的文档。
5. 厂商参考 XDC 只能逐项摘取已核验条目，不得整份加入工程。

## 7. 基线结论

当前项目已经具备可靠的方案和评审框架，但还没有可用于判断定位精度、音频改善、FPGA 资源或稳定性的实物证据。今晚的有效推进不是开始复杂算法 RTL，而是把板卡、外设、接口、负责人和验收证据冻结到可执行状态。
