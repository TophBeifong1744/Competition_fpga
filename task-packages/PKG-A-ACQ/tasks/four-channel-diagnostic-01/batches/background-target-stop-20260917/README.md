## 保存方法与容量

现有短抓取固定 32000 组，每组 32 字节，共 1024000 字节，48 kHz 下约 0.667 秒。现有 E1 可以连续运行但在线检查后回收两槽，没有完整长录音，串口不是声学输入。当前方案不引入尚未核实的 SD/网络录音路径，也不尝试以 115200 波特串口实时传输 1,536,000 字节/秒原始流。

拟新增 CPU 所有的静态留存数组，放入**已有程序区**的 `.bss`，由链接器分配，而不是写死一个任意新 DDR 地址：

| 区域 | 原合同 / 规划 |
| --- | --- |
| 程序区 | 现有 lscript.ld 为 `[0x00100000,0x01000000)`，15 MiB；包含代码/静态数据/堆栈。 |
| DMA RX 保留区 | 保持 `[0x01000000,0x01100000)`；两槽各8000+64字节，共16128字节。 |
| 6 秒目标 | 288000组 × 32 = 9,216,000 字节；以连续样本编号和实际组数报告时长，不只以CPU计时。 |
| 拟定留存容量 | 300000组 × 32 = 9,600,000字节，另加首尾各64字节保护和对齐；留出完整包停止/排空余量。 |
| 容量判断 | E1现有程序end=0x00113890，静态留存的容量估算可在既有15MiB程序区内容纳。**新符号实际地址、长度、堆栈/段边界必须在新map/ELF重新核实，不能把估算当最终地址。** |

数据流：PL持续采样 → 原两槽DMA → CPU获取并验证完成包 → 原字节复制到留存数组 → 才释放该槽。留存区不交给DMA，不覆盖尚待CPU处理的槽；新开销需模型/边界测试及本次实际状态记录，不能用旧E1时序代替验证。

达到目标后只请求一次停止，继续接收完整包并排空；停止余量不足即明确失败，禁止越界/静默丢包。失败保留已保存长度、首错、失败槽/保护区和状态，不重置清错后当作同一次继续。数据中原始ID、四路PCM、flags及reserved逐字保留；饱和等非致命标志不被清除。

排空、停止写入后，flush CPU写过的留存数组至DDR，再计算/报告实际组数、地址、字节/字数、首尾ID、校验值、错误/保护区/状态。用户只在READY之后用既有XSDB `mrd -bin` 导出该实际区间；输出未保存前不再次Run/复位。没有在采集中暂停CPU做JTAG读取。

这是新增静态数据占用，而不是“零内存改动”；不扩大旧RX或改链接脚本范围，不复用旧固定合同的PASS放行新固件。新配置应显式版本化，增量检查绑定实际留存符号、容量/guard、程序边界、调度、对象/ELF、实际编译链接参数与加载文件；旧E1入口和待审21c141b均不后台替换。未知配置拒绝，不能关掉检查器绕过不匹配。

## 录制安排

- 一次真正连续的约6秒数据：建议背景约2秒 → 目标语音约2秒 → 目标停止后的同场景背景约2秒；允许完整包尾部余量。目标停止后采集仍继续，不能停止发声时同时停止采集。
- 阵列及声源位置固定、整段共用配置/增益；沿用已声明的四麦几何/坐标轴，现场变动如实更新。方向/距离以阵列中心为参考，可沿用+X、约1.5m、近似同高安排，但未操作/确认前不写成此次实测；记录量法与估计误差，未知填未知。
- 优先现有设备播放一个已知语音文件，记录设备、原文件SHA-256、内容、音量和音效/AGC等已知设置；背景就是目标未发声时的同场景声音，不是独立纯噪声真值。
- 播放文件里的静音/发声时间可以精确描述**源文件时间轴**，不等于阵列PCM样本的精确起止；没有硬件同步时播放/Run时间只作辅助。可用操作录像/时间记录和录音波形事后标注活动区间，并明确人工估计及误差，不交给B冒充独立样本真值。现场人声同样只做近似/事后标注。
- 不采购、不向C派任务、不要求精细仪器补证；明确错电源、短路、输出争用仍立即停止相关操作。当前已知旧bit误加载、相机共享引脚风险沿[统一风险记录](../../../../../../docs/deferred-acquisition-risks.md)处理。

## 导出和检查复用

- 复用 `source/export_four.py` 的32字节解码及H1导出函数，其核心不限定32000组；保持 signed24/int32、原ID与flags。
- `source/export_c_capture.py` 和旧 `finish_capture.py` 的录音配对入口固定了短抓取长度/日志格式，不能原样拿来放行新录音。仅新增本批日志/留存合同适配，复用底层解码/已有读取器及WAV转换，不改旧文件。
- 新BIN要独立重算全部ID/组数/flags、四路min/max/zeros/clip计数和校验值，并关联完整串口、留存长度和配置版本；不能只依赖日志PASS。若复用E1解析代码，补齐B指出的成功游标、最后值signed24/通道范围、zeros与min/max的关联检查，负例保留。
- 复用 `task-packages/PKG-B-ALG/payload/model/python/h1_reader.py`；新config_version显式记录保存路径改变，原PDM/CIC仍是上游DSP，不能笼统写PCM“完全未经处理”。
- WAV是派生试听，不改BIN/CSV；整段及四通道使用同一固定缩放（已有共同增益12仅在本次不会引入额外削顶时复用），不做逐段归一化、去直流或滤波掩盖差异。若需较小共同增益，整段统一并记录公式/舍入/削顶检查。
- 软件增量检查包括槽释放必须晚于复制、跨槽/全段ID、尾包/容量/guard、停止排空、超时与错误留存、导出缓存flush、BIN/日志错误配对、元数据与读取器；不重测未变的整套DDR、RTL或五分钟耐久。
