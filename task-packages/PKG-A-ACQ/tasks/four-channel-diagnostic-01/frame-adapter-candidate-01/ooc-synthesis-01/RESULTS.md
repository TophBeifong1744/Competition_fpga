# 四路重叠分帧候选 OOC 综合结果

结论：**冻结候选在空的 xc7z020 上能够完成 OOC 综合，已约束的内部路径综合估算满足 100 MHz；但 1024×196 bit 缓存全部实现为分布式 LUTRAM，消耗 4364 个 LUTRAM（可用 LUTRAM 的 25.08%），没有推断出任何 BRAM。当前结构能放下，但不适合作为后续正式算法链的资源形态，接入 `one` 前应优先改为同步读、BRAM友好的结构。**

本结论不等于布局布线、接口时序、实际工程接入、CDC、实板、实时闭环、M1 或 H3 通过。

## 2. 资源和存储器推断

| 资源 | 使用量 | 器件可用量 | 占比 |
|---|---:|---:|---:|
| Slice LUT | 5629 | 53200 | 10.58% |
| LUT as Logic | 1265 | 53200 | 2.38% |
| LUT as Memory / Distributed RAM | 4364 | 17400 | 25.08% |
| Slice FF | 783 | 106400 | 0.74% |
| F7 / F8 Mux | 392 / 196 | 26600 / 13300 | 各 1.47% |
| RAMB36 / RAMB18 | 0 / 0 | 140 / 280 | 0% |
| DSP | 0 | 220 | 0% |

Vivado识别出一个 `1024×196 bit` 的 `groups_reg`，初步及最终推断均为 Distributed RAM。技术映射后是 1082 个 `RAM64M` 和 18 个 `RAM64X1D`，折算 4364 个 LUTM；`report_ram_utilization` 明确显示 BlockRAM 为 0。综合还提示其中4位没有负载、宽度可能由196缩为192，但最终资源报告仍应作为本轮实际证据，不能据此自行改合同。

根因与 RTL 结构一致：`wire [195:0] head=groups[rd_ptr]` 是异步组合读，另有 `groups[frame_start]` 的动态读取。7系列 BRAM适合时钟同步读；当前异步读和多读地址形态使 Vivado选择分布式 RAM。大量 LUTRAM还产生明显的地址控制扇出：高扇出报告中多个 `wr_ptr` 复制网扇出约575～674。这会增加后续布局布线压力，尽管本次尚未实现。

因此资源判断是：**空器件上可综合、总 LUT 尚未超限，但用约25 KB缓存消耗四分之一可用 LUTRAM并不经济。** 后续 FFT、PHAT和控制逻辑仍需要 LUT/布线资源，本结果支持在正式接入前重构存储结构。

| 指标 | 结果 |

| 目标周期 / 频率 | 10.000 ns / 100 MHz |
| WNS | +2.612 ns |
| TNS | 0.000 ns |
| Setup失败端点 | 0 / 32311 |
| 最差脉宽裕量 | +3.870 ns，0个失败端点 |
| Hold | 本次只运行 max-delay 综合报告，未给出实现后 hold 结果 |

当前最差内部路径的数据延迟为6.890 ns、21级逻辑，主要经过64位原始 ID 连续性比较形成的 CARRY4 链，再扇出到状态/指针复位控制；它不是 RAM 数据输出路径。综合报告估算该内部路径满足100 MHz。

这个 WNS有三个重要边界：

1. 尚未 `opt/place/route`，其中3.233 ns为未布局状态下的估算布线延迟。
2. OOC没有指定真实时钟源位置；Vivado警告未设置 `HD.CLK_SRC`，因此时钟延迟/偏斜估计不完整。没有为了美化结果填造位置。
3. `check_timing` 报告303个输入端口和683个输出端口缺少 I/O delay，共986项 `TIMING-18`。内部寄存器端点没有未约束项，但异步 LUTRAM直接到 `m_*` 输出的接口路径没有下游捕获寄存器/真实接口延迟，所以 **+2.612 ns不能证明输出接口在接入后满足100 MHz**。

## 4. 帧输出、输入暂停与背压

在 `m_ready=1` 时，每帧确实产生1024次连续输出握手。按现有状态机：

- 接受填满帧的最后一个输入组后，有1个启动周期才拉起输出；
- 随后输出1024拍；
- 这段时间 `s_ready=0`，从填满帧到再次可接收输入共暂停1025个周期，即100 MHz下约10.25 us；
- 第一帧需先接收1024组；之后每接收512个新组，再经历上述输出暂停；
- 任意 `m_ready=0` 都会逐周期延长暂停，协议允许下游无限背压。

对48 kHz采样率，512组约10.667 ms，正常无背压时平均计算时间有较大余量；但物理 PDM/CIC不能因这10.25 us暂停，更不能承受无限背压。因此本模块只能接可暂停的 DDR读取器或前置缓冲。真实连续链仍必须具备有限 FIFO/DDR所有权、最坏服务时间预算，以及“缓存满/丢组/溢出”的可观测错误路径；本次综合没有证明这些条件。

## 5. 警告及失败历史

- 综合阶段本身报告0 error、0 critical warning、0 warning；完成后的Vivado日志有4条普通 warning：大扁平网表不利于floorplan、OOC时钟源位置未知，以及两次OOC DRC覆盖不完整。
- DRC中的 `ZPS7-1` 是对Zynq器件没有PS7单元的警告；本任务明确只综合独立 PL 顶层，所以它是OOC边界，不代表实际 `one` 可以缺少PS。
- `TIMING-18` 共986项是缺少真实 I/O delay，按任务要求如实保留。
- `ooc_20260918_01` 在综合前因 `-tclargs` 顺序错误被拒绝；`ooc_20260918_02` 在读取RTL前后因含空格路径未封装为Tcl list失败。两次日志均保留，均不能算综合结果；`_03` 是唯一完成的OOC运行。

## 6. 最小重构建议（未实施）

1. **同步读、分银行 BRAM环形缓存**：把196位拆成若干BRAM宽度银行，采用同步读和一级输出保持寄存器；独立跟踪 `first_id`，移除第二个异步动态读。容量下限约为6个RAMB36（实际以配置和综合为准）。优点是大幅释放LUTRAM；代价是读延迟增加1拍，握手与 `m_last` 必须重新仿真。
2. **在方案1上增加输入/输出解耦**：使用双缓冲或更深的双口BRAM环并加入占用计数和显式overflow事件，使读帧时仍可接收新组。容量和控制复杂度上升，有限缓存仍不能吸收无限 `m_ready` 背压，但能消除当前每帧固定暂停。该方案只有在后续实际服务延迟预算确定后才应定深度。

本轮不修改冻结RTL；不通过 `ram_style` 强迫不兼容的异步读结构映射BRAM。
