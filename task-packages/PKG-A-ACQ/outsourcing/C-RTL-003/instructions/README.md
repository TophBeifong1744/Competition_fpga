# C-RTL-003：四通道 PCM 符号扩展与打包操作单

版本 1.0；日期 2026-09-09。本批只做这一项：一个组合 RTL 小模块、自动自检 TB 和原始日志。暂不连接总工程。

## 1. 现在要做什么

按 H1 候选数据约定，四路有符号 PCM 需要保持数值，扩展为各 32 位，并明确 mic0 在低位的打包顺序。你只实现这段确定的位级转换，不做采集、滤波或算法。

这是 A 的临时外包，正式分工不变；本聊天独立验收，B 正式复核，A 决定后续是否接入。无需等麦克风、DDR、PYNQ、002 集成或录音到齐，可直接写 Verilog .v。Vivado/XSim 固定 2025.2，如需器件用 xc7z020clg400-2。

H1 默认 24 bit 是候选交换码值范围，不等于 PDM 麦克风有效精度或正式采集位宽。此模块的 128 位输出是内部测试/转换向量，不是已批准的 AXI DMA 字宽或内存字节序合同；不得修改 H1 文档或宣称四麦声学验证。

## 2. 固定接口

模块名 pcm4_signext_pack；参数 SAMPLE_WIDTH 默认 24，必须支持 2～32。参数是编译期常量，不添加运行时配置。

| 端口 | 方向 | 位宽/类型 | 含义 |
|---|---|---|---|
| mic0_in | 输入 | signed [SAMPLE_WIDTH-1:0] | 通道 0 的二进制补码样本 |
| mic1_in | 输入 | signed [SAMPLE_WIDTH-1:0] | 通道 1 的二进制补码样本 |
| mic2_in | 输入 | signed [SAMPLE_WIDTH-1:0] | 通道 2 的二进制补码样本 |
| mic3_in | 输入 | signed [SAMPLE_WIDTH-1:0] | 通道 3 的二进制补码样本 |
| pcm_packed | 输出 | wire [127:0] | 四个 32 位补码槽位组成的向量 |

没有时钟、复位、valid、ready、事件、sample_id 或配置端口。纯组合输出，输入变化后组合传播完成即更新，不保持历史状态，不使用锁存器。

## 3. 唯一转换规则

每个输入的原 SAMPLE_WIDTH 位保持不变，高出的 32-SAMPLE_WIDTH 位全部复制该输入符号位。不得零扩展负数、左对齐、缩放、舍入、饱和或截断。

| 输出片段 | 内容 |
|---|---|
| pcm_packed[31:0] | mic0 的 32 位符号扩展值 |
| pcm_packed[63:32] | mic1 的 32 位符号扩展值 |
| pcm_packed[95:64] | mic2 的 32 位符号扩展值 |
| pcm_packed[127:96] | mic3 的 32 位符号扩展值 |

SAMPLE_WIDTH=32 时逐位原样输出；不要产生负重复次数或截断最高位。四个槽位各自按 signed32 解读，整个 pcm_packed 不当作一个有符号音频数值。

默认24位例子（向量按最高位到最低位写）：

| 输入 mic0/mic1/mic2/mic3 | 预期 pcm_packed |
|---|---|
| 0 / 1 / -1 / -8388608 | 128'hFF800000_FFFFFFFF_00000001_00000000 |
| 8388607 / -2 / 2 / 0 | 128'h00000000_00000002_FFFFFFFE_007FFFFF |

这是数字码型测试，不是声学模拟或硬件实录。物理通道接线、通道时间同步由 A 负责，此模块不会“修复”错接线或采样不同步。

## 4. 按操作顺序执行

1. 建立 submission/rtl/pcm4_signext_pack.v，按接口表声明端口和参数，用组合连接完成四路扩展和拼接。
2. 建立 submission/tb/tb_pcm4_signext_pack.v，驱动输入后留出仿真调度时间，再自动比较完整 128 位结果；RTL 里不写 # 延时，TB 可以使用。
3. 先测默认24位的两个例子，再增加 2、3、16、32 位实例；默认24位实例不覆盖参数。
4. 参考模型按“无符号码值若最高位为1，则减去 2^SAMPLE_WIDTH”取得数学整数，再生成32位预期。使用足够宽的参考变量（例如 signed64）；不要直接复制 DUT 的拼接表达式作为唯一判据。
5. 完成下表必测用例。每次比较用 !==，不匹配打印参数、输入、期望/实际并 $fatal；全部通过才输出 ALL TESTS PASS，加入超时退出。
6. 用 Vivado 2025.2 的 xvlog 不带 --sv 编译新 .v 文件，再展开、运行；保存真实编译、展开、仿真日志和完整运行步骤。无需公共验证框架或 UVM。
7. 填写提交模板、生成文件清单，在本 submission 目录完整打包交付。不要为每条语句或每次实验分包。

## 5. 必须自测

| 检查 | 要求 |
|---|---|
| 正负边界 | 每路分别测 0、1、-1、最大正数、最小负数、最小负数+1 |
| 四路顺序 | 四路同时输入不同值，逐槽位确认；只改一路时其他三槽不变 |
| 符号独立 | 覆盖四路正/负符号的全部16种组合，排除共用某一路符号位 |
| 位保持 | 每路每个位 walking-one / walking-zero，其他通道固定不同码值；包含32位最高位 |
| 参数边界 | 2、3、16、默认24、32全部通过；32位零扩展长度情况必须可编译 |
| 小位宽穷举 | SAMPLE_WIDTH=2 时遍历四路全部 4^4=256 个码型组合 |
| 组合行为 | 连续多次无时钟改输入，输出都随之改变，不能只在某个初始化时刻计算一次 |
| 可重复随机测试 | 16、24、32位各至少256组固定种子输入，参考值独立计算，不经浮点 |

最低交付不要求所有2～32位逐一跑完，也不要求错误注入框架。可以扩展测试，但先完成必测项，不将本批变成开放式研究。

- 需要增加寄存器、AXI、DMA、CDC、FIFO、采样编号或修改001/002时，停止扩展并反馈。本任务无这些职责。
- 编译/仿真失败先保留原始日志，修正自己的代码后重跑；不要改期望迁就错误。
- 综合可选，未运行写 NOT_RUN；环境受阻保存错误，不重装或重置全局环境。组合连线模块综合后可能没有逻辑单元，不能据此虚构处理速度或时序通过。
- 功能通过后交本聊天独立验收，再交 B 正式复核；未经批准不合入总工程。
