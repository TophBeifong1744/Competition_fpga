# C-RTL-001：错误统计 RTL 外包说明

版本：1.0；日期：2026-09-08。**本批只做这一项。**

## 1. 你需要完成什么

编写一个单时钟 SystemVerilog 模块 `stream_error_stats`，分别统计溢出事件与丢样事件，并保存“曾经发生错误”的标志。再写一个可自动判断对错的简单测试平台。

这项工作属于 A 的 `PKG-A-ACQ`，由 C 临时实现，不改变原分工。本聊天检查代码和独立测试；父包仍由 B 复核并合入。**无需麦克风、开发板、PYNQ 或整个系统准备完成，先独立写模块和仿真。**

工具基线为 Vivado 2025.2。若需要选择器件，使用项目已确认的 `xc7z020clg400-2`。不要求重建现有 one 工程，也不要求下载到板卡。

## 2. 固定接口，不自行扩展

模块名：`stream_error_stats`。

参数：`COUNT_WIDTH`，整数，默认 32；必须支持 1～64，其他值不在本次规格内。

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---|---|
| `clk` | 输入 | 1 | 唯一时钟，上升沿采样 |
| `rst_n` | 输入 | 1 | **同步、低有效复位**，在时钟上升沿为 0 时复位 |
| `clear` | 输入 | 1 | 同步清除两类计数及保持标志 |
| `overflow_event` | 输入 | 1 | 本周期有一个溢出事件 |
| `drop_event` | 输入 | 1 | 本周期有一个丢样事件 |
| `overflow_count` | 输出 | COUNT_WIDTH | 无符号、饱和的溢出事件计数 |
| `drop_count` | 输出 | COUNT_WIDTH | 无符号、饱和的丢样事件计数 |
| `overflow_sticky` | 输出 | 1 | 溢出事件保持标志 |
| `drop_sticky` | 输出 | 1 | 丢样事件保持标志 |

输入均已与 clk 同步，由 A 的后续集成提供；本模块不做同步器或边沿检测。事件连续为 1 三个周期，就累计三次。两类事件同周期发生时分别计数。

这里统计的是**事件次数**，不是一次溢出实际丢掉多少个样本。不要自行推断丢样数量，不产生或修改采样编号。

## 3. 行为优先级

每个时钟上升沿，按以下顺序决定新状态：

1. 若 `rst_n=0`，全部输出置 0，忽略 clear 和事件。
2. 否则若 `clear=1`，先清掉历史，再计入本拍事件：对应 event=1 时，该路 count=1、sticky=1；对应 event=0 时，该路 count=0、sticky=0。
3. 否则，对每一路独立处理：event=1 时 sticky 置 1，计数未满则加 1、已满则保持；event=0 时计数与 sticky 均保持。

COUNT_WIDTH 位计数器最大值为全 1。**达到最大值后不允许回绕到 0**。饱和状态下也能被 clear 或复位清除。

输出全部是寄存器状态，在采样上升沿后更新，不增加额外流水级。没有 valid/ready 握手；不能让其中一路事件控制另一路。

### 对照例子（仅示出 overflow 一路）

| 旧 count / sticky | rst_n | clear | event | 上升沿后的 count / sticky |
|---|---:|---:|---:|---|
| 5 / 1 | 0 | 1 | 1 | 0 / 0 |
| 5 / 1 | 1 | 1 | 0 | 0 / 0 |
| 5 / 1 | 1 | 1 | 1 | 1 / 1 |
| 5 / 1 | 1 | 0 | 1 | 6 / 1（位宽足够时） |
| 最大值 / 1 | 1 | 0 | 1 | 最大值 / 1 |
| 1 / 1 | 1 | 0 | 0 | 1 / 1 |

1. 先按第 2 节建立端口和参数，写复位、清零、独立事件计数与饱和逻辑。

3. 先用 COUNT_WIDTH=3 测通，再测 1、默认 32 与 64。小位宽用于快速跑到饱和，不需要仿真数十亿周期。

## 5. 必须自测的内容

| 用例 | 必查结果 |
|---|---|
| 复位与空闲 | 复位归零；空闲不变；同步复位不能在无时钟上升沿时改变状态 |
| 复位优先 | 复位、clear、两个事件同时有效，全部归零 |
| 单路事件 | 只改变对应一路，不影响另一路 |
| 连续事件 | 连续三个周期为 1 就加三次，不只计上升沿 |
| 两路同拍 | 两路均正常累计、标志均置位 |
| 标志保持 | 事件结束后 sticky 不自动消失 |
| 普通清零 | clear=1、无事件，两路全部归零 |
| 清零与事件同拍 | 分别覆盖仅 overflow、仅 drop、两者都有；各路结果为 0 或 1 |
| 连续清零 | clear 连续有效且 event 持续为 1，每拍对应 count 都是 1，不继续累加 |
| 饱和 | COUNT_WIDTH=1、3 分别到达最大值，再来事件仍保持，不回绕 |
| 饱和后清零/复位 | 清零可重新计数；复位仍优先 |
| 参数宽度 | COUNT_WIDTH=1、3、32、64 均可编译；32、64 做基本功能测试 |

可以用一个参数化测试平台分次运行，也可在同一平台实例化不同位宽。无需搭建公共验证框架，不需要 UVM。
