# C-RTL-002：错误统计快照 RTL 外包操作单

版本：1.0；日期：2026-09-09；本批唯一任务。预期交付是一个小模块、自动自检 TB、运行步骤和原始日志，不是完整采集工程。

## 1. 用途和边界

A 的采集链路已有 C-RTL-001 两路错误计数和 sticky 标志。本模块根据一次请求，在同一时钟沿把这四项一起保存；没有请求时，保存值不随实时计数变化。A 后续可选择将它接到状态读取逻辑，但本批不设计寄存器地址、不连接 PS，不保证跨时钟读取安全。

这是 A 任务内的临时外包，不改变正式分工。C 按此操作单实现，本聊天独立测试，B 正式复核。工具固定 Vivado/XSim 2025.2；如需器件用 xc7z020clg400-2。无需麦克风、板卡、PYNQ、DDR、录音或 H3 算法评审，今天即可建立独立模块开始写代码。

## 2. 唯一接口

模块名 stream_error_snapshot；参数 COUNT_WIDTH 默认 32，合法范围 1～64。只需保证此范围，非法参数不在本批验收范围。

| 端口 | 方向 | 位宽 | 固定含义 |
|---|---|---|---|
| clk | 输入 | 1 | 唯一时钟，上升沿采样 |
| rst_n | 输入 | 1 | 同步低有效复位 |
| snapshot_req | 输入 | 1 | 每个高电平周期请求一次快照，不做边沿检测 |
| live_overflow_count | 输入 | COUNT_WIDTH | 实时溢出事件计数，无符号 |
| live_drop_count | 输入 | COUNT_WIDTH | 实时丢样事件计数，无符号 |
| live_overflow_sticky | 输入 | 1 | 实时溢出标志 |
| live_drop_sticky | 输入 | 1 | 实时丢样标志 |
| snapshot_overflow_count | 输出 | COUNT_WIDTH | 保存的溢出计数 |
| snapshot_drop_count | 输出 | COUNT_WIDTH | 保存的丢样计数 |
| snapshot_overflow_sticky | 输出 | 1 | 保存的溢出标志 |
| snapshot_drop_sticky | 输出 | 1 | 保存的丢样标志 |
| snapshot_valid | 输出 | 1 | 本拍完成快照更新的寄存器指示，不是永久有效标志 |

所有输入已同步到 clk，由集成方保证。这里不做统计、不饱和运算，也不推断 count 与 sticky 的关系；四项原样采样，即使测试输入 count 非零而 sticky 为零也原样保存。

## 3. 逐拍行为，严格按此实现

每个上升沿只有两层优先级：

1. rst_n=0：全部输出清零，忽略请求和实时输入。
2. rst_n=1：snapshot_valid 更新为 snapshot_req；若 snapshot_req=1，四个保存输出同时更新为该沿采到的四个 live 输入；否则四个保存输出保持。

没有 busy/ready、没有队列、没有 clear、没有额外流水级。snapshot_req 连续为 1 时每拍重新取快照，snapshot_valid 也连续为 1，不要求两次请求之间插空拍。请求停止后的第一个上升沿 snapshot_valid 变零，但数据继续保持，直到下次快照或复位。

示例（每行表示沿后状态，计数按 overflow/drop 顺序）：

| rst_n | req | 沿前 live 计数 | 沿后快照计数 | 沿后 valid |
|---:|---:|---|---|---:|
| 0 | 1 | 5/7 | 0/0 | 0 |
| 1 | 0 | 5/7 | 0/0 | 0 |
| 1 | 1 | 5/7 | 5/7 | 1 |
| 1 | 0 | 6/8 | 5/7 | 0 |
| 1 | 1 | 9/10 | 9/10 | 1 |
| 1 | 1 | 11/12 | 11/12 | 1 |

例子适用于能表示这些数值的位宽；小位宽测试使用范围内码值。

### 与 C-RTL-001 同沿连接时的重要规则

两个模块都在上升沿使用非阻塞赋值。如果统计模块在该沿将计数从 5 加到 6，快照模块在该沿看到的是更新前的 5。这是本任务约定的行为，不是错误。不增加组合“预加一”，不改 001。需要包含该沿新事件时，由 A 在后续一拍发快照请求。

## 5. 必须测试的内容

| 测试 | 必查结果 |
|---|---|
| 复位与请求同时有效 | 所有输出为 0 |
| 同步复位时机 | 两个上升沿之间拉低 rst_n，不得立即清零；下一上升沿才清零 |
| 初始无请求、live 持续变化 | 复位后的快照保持零，valid=0 |
| 单拍请求 | 同时捕获四项，valid=1；下一拍无请求 valid=0，快照保持 |
| 连续请求、四项每拍变化 | 每拍捕获，不漏拍，不使用边沿检测 |
| 两请求之间长时间空闲 | 保存值不被 live 后续变化覆盖 |
| 数据边界 | 0、全 1、最高位单独置 1、交替位；64 位最高位不能被截断 |
| sticky 四种组合 | 00/01/10/11 均原样保存，包括 count 与 sticky 不一致的人工输入 |
| 请求改变的时机 | 上升沿之间改变 req/live，不得异步改变任何输出 |
| 复位后重新请求 | 从零状态恢复，valid 与数据同拍更新 |
| 参数 | 1、3、默认32、64 均编译与功能通过 |
| 与 001 的小型联合仿真 | 连接已验收 001；同沿 event+req 捕获旧计数，下一拍 req 捕获更新值；同沿 clear+req 捕获 clear 前值。仅为两个小模块 TB，不做系统集成 |

联合仿真可只用 COUNT_WIDTH=3；复位同时接两个模块。001 依赖固定为 ac8a7bb60d94c069f5f1b61e9fc38658b0742962 中 submission/rtl/stream_error_stats.sv。可在独立测试目录复制此文件，交付时放入 submission/reference/，记录来源提交及 SHA-256，不修改参考文件。它不算第二项外包任务。
