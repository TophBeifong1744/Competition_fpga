# C-RTL-002 自查报告 v1.1

日期：2026-09-09。审查者：Codex（作者自查，不是独立第三方或 B 批准）。
范围：操作单逐项对应、RTL静态检查、正向/负向仿真、独立综合、交付一致性。
结论：本次未发现RTL功能缺陷；v1.0的测试覆盖可以加强，已补齐下列缺口并实际重跑。

## 已关闭的发现

| 发现 | 原来的局限 | 本次处理与证据 |
|---|---|---|
| 中间位接错的检测能力不足 | 固定0/全1/最高位/交替位不能区分部分同奇偶位置，中间位串接可能漏检 | 增加每位walking-one/zero；第17位故意取第19位时，在32位 walking one overflow only 被检出 |
| 沿间短脉冲检查不够独立 | 原来有组合req/live/reset脉冲，单个信号短脉冲和短暂输出变化没有分开覆盖 | 独立请求、数据、复位脉冲；连续监视输出只能在上升沿变化，异步复位错误被实际检出 |
| 规格内其余位宽未逐一运行 | 原来仅1、3、32、64 | 本次1～64全部展开与仿真通过，默认32不覆盖参数 |
| 联合测试缺少饱和及部分clear组合 | 原来15步已覆盖操作单基本同沿要求 | 扩展到32步，包含真实计数至7、保持饱和、clear事件四组合、连续clear及无req时clear |
| 可综合性仅凭源码风格判断 | 原来综合NOT_RUN | 本次1、32、64独立综合成功，寄存器数量和类型符合设计 |

这些发现是验证覆盖与证据缺口，不代表正式RTL曾实现错误。
正式RTL和001参考的SHA-256均与v1.0相同，没有通过修改期望值掩盖错误。

## 静态审查

- 模块名、默认参数、端口方向/位宽匹配操作单；后续用户明确要求.v，因此源文件扩展名调整已记录。
- 唯一always块只在clk上升沿运行；同步低有效复位优先于请求。
- 非阻塞赋值同时捕获四项；valid每拍更新，不是sticky或延迟一拍。
- 未请求时数据寄存器保持；连续请求逐拍捕获；数据不做算术和一致性推断。
- 全部计数信号按COUNT_WIDTH声明，清零按COUNT_WIDTH复制零，无固定32位中间变量。
- 没有多时钟、组合锁存、额外控制接口、隐式计数或001修改。
- 测试在下降沿驱动，上升沿1ns后比较，避免与非阻塞更新竞争；四态比较使用!==。
- DUT 32位实例不带参数覆盖；1～64测试的其余实例明确传参。
