# RTL 语言与 Block Design 接入约定

版本：rtl-bd-policy-1.0；日期：2026-09-10。来源：拓芙在工程实现任务中明确要求；适用于本项目后续 RTL 交付与 Vivado 2025.2 集成。

## 1. 统一规则

- 简单功能模块默认用 Verilog，文件扩展名 `.v`，例如计数、分频、脉冲、简单状态机、接口包装与打包逻辑。
- 复杂模块确实受益于 SystemVerilog 的类型、数组、包或参数化表达时，可用 `.sv`，交付说明中注明原因，不为使用语言特性增加复杂度。
- 采用当前 BD 的 Add Module / Module Reference 流程时，提供纯 Verilog `.v` 顶层。若内部核心是 `.sv`，由 `.v` 包装模块实例化它；BD 添加包装模块，不直接添加 SV 核心。
- 自检 testbench、断言与仿真模型可继续用 `.sv`，放入 Simulation Sources，不受“简单可综合模块优先 `.v`”限制。

这替代原 `rtl/README.md` 中“新代码优先使用 SystemVerilog”的默认约定。既有已验证 SV 核心不批量翻译为 Verilog，按接入需要补包装层并验证即可。文件名应与其主要模块名一致，语言类型须与实际语法相符。

## 2. 限制的范围与项目依据

本项目 one 工程中，用户将 `test_source.sv` 直接作为 Module Reference 添加到 BD 时，Vivado 报告其顶层文件类型 SystemVerilog 不允许用于该引用；改用 `test_source_bd.v` 实例化 SV 核心后完成接入。这是当前流程采用 `.v` 外壳的实际依据，不是宣称 Vivado 不支持 SV 综合或仿真。

不要把此规则泛化成所有版本、所有 BD 接入方式的语言限制。打包自定义 IP 是不同入口，需要独立验证；它不是当前默认方式。也不要仅把 `.sv` 改名 `.v`：`logic`、`always_ff`、`interface` 等 SV 语法不会因此变成 Verilog。

## 3. 包装层职责

包装层只做明确的端口、参数和必要的类型边界映射。保持原核心的时钟、复位极性、数据位宽、有符号解释、通道顺序、握手、包尾和流水延迟；不得顺便改缩放或增加未记录的寄存器延迟。

- 对 BD 暴露普通标量或一维 packed 向量；不要直接把 SV interface、struct、unpacked array 或 package 自定义类型当作外部端口。
- SV 核心及其 package/include 依赖仍需作为正确类型的源码加入工程，并核对编译顺序。只有一个 `.v` 外壳并不能弥补缺失依赖。
- AXI 接口属性、关联时钟和复位属性放在可见包装层，检查 BD 识别出的端口方向与宽度；自动识别失败不等于内部算法错误。
- 包装层是 BD 中的一个模块，不是把整个 BD 工程顶层从 `system_wrapper` 改成该模块。

## 4. 交付与验收

模块交付说明必须列出：核心语言、BD 入口模块、源码与依赖清单、接口版本、参数、位宽/符号/缩放、时钟/复位和验证状态。

1. 先运行核心自检；存在包装层时，再验证包装后的对外行为，包括负数、边界值、复位、背压、TLAST 等适用情况。
2. 将综合源码加入 Design Sources、测试代码加入 Simulation Sources；不重复导入同名模块。
3. 在实际 Vivado 2025.2 工程中检查 Module Reference 可添加、接口识别与参数正确，执行 Validate Design。
4. 仿真、模块综合、整板实现与时序、板上测试分别记录结果。能添加到 BD 不代表后续验收通过。

## 5. 其他任务对齐要求

主流程负责将本规则纳入后续工作包和外包说明；工程实现、拓芙工作执行、H2 集成/证据任务，以及后续 A/B/C RTL 作者与复核人统一引用本文，不另立冲突版本。

新交付按本文执行；正在进行的交付先核对实际 BD 入口，必要时补 `.v` 包装与验证。仅离线 SV 模型或已有合格包装的核心无需重写。历史批准快照、原始证据及其哈希保持不变，不能为统一文案修改旧验收材料。

本规则只调整语言选择和工程接入方式，不改变 PCM 位宽、DMA 打包、时钟频率、PL/PS 分工或阶段验收边界；这些仍按对应接口合同执行。各任务不得因本通知并行修改同一个 one/BD/PS 工程。
