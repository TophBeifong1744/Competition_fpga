## 已有证据

- 单通道，配置 48 kHz，每次 48000 样本，约 1 秒；实际时钟未测。
- 两次用户标注为固定位置安静/歌曲对照。BIN 与用户串口 FNV、编号、最小最大值、零数及状态字段逐项一致；错误/削顶标志均为零。
- 安静 FNV EFFF882A，ID 14223..62222；歌曲 C7762DD9，ID 13352..61351。
- 原始 signed24 PCM 放在 int32 中；每条 16 字节：ID low32、ID high32、PCM signed32、flags32；250 条一包，192 包共 768000 字节。
- 配置 PDM 3.072 MHz，CIC3/R64/M1，启动丢弃4096输出样本。原始编号不重编号。具体实现见 snapshot 的 RTL 和 C 源码。
- map：end=0x00112220；程序分配 [0x00100000,0x01000000)，接收预留 [0x01000000,0x01100000)，不重叠。源码先 flush/invalidate、DMA 后 invalidate，检查后置64字节保护区。
- 用户此前明确能听出第二次试采中的歌曲；本包最新固定位置对照尚未收到用户试听确认。
- 最新对照100..8000Hz加窗能量增加5.596dB，1000..8000Hz增加12.507dB。不是SNR或频响。100Hz以下占比安静97.943%、歌曲91.028%，低频来源未定位。

## 文件

- quiet_music/：两份原始BIN、原幅度24bit WAV、同增益试听、comparison.json（含来源、处理说明与哈希）。试听去各自直流并使用同一增益；不替代原始信号。
- serial-user-transcript.txt：用户粘贴日志，已还原 Markdown 转义；不是串口工具原始日志文件。
- snapshot/：当前工作文件只读复制，包括RTL、XDC、BD、平台XSA、运行配置引用的bit、ELF、C源码、链接脚本和map。
- snapshot-manifest.json：来源路径、修改时间、SHA256。快照是在采集后取的，不能倒推证明板上当时加载的每个字节；需审核者结合launch配置/用户下载过程核实。并非从零重建工程包。
- check_quiet_music.py：本次检查脚本的原样快照，保留原始本机输入/输出路径；重跑前需改输出目录，脚本拒绝覆盖。

## 验收边界与缺项

- 建议只验收“单麦真实声音初步采集与传输完整性”，由执行任务独立裁定。
- 不声称四路H1、H2、定位精度、完整音质或最终滤波通过。
- 当前XDC只有引脚与电平；PDM外部时序约束、实际CLOCK/DATA相位与电气测量尚缺证据。
- 用户报告比特流与时序资源无报错；本包未独立归档本版完整实现报告，不把用户反馈写为独立时序验收。
- 原理图支持Bank13默认3.3V；当前任务尚未获得VCCO实测记录。用户称板卡供电正常，不能替代该记录；执行任务可核对其持有的最新硬件资料。
- CIC诊断链低频占比高，根因未定位；暂不通过高通/增益改动掩盖。是否需追加测试由执行任务派发。
- 不使用旧decode_mono.py自动宣称hardware-audio来源；本包明确按用户标注追溯，未冒充四路交换合同。
- 本次整理未修改活动工程、未提交Git；继续补齐当前阶段必要项，验收后才等待新任务。
