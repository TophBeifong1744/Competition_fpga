# Formal FPGA project layout

The scaffold creates a clean, vendor-specific project. Generated and formally normalized projects always use the canonical names below. Never generate numbered variants such as `project2`, `par2`, or `script2`. Existing foreign layouts may be read or imported, but normalized output uses this structure. Optional directories are created only when requested.

```text
<project-root>/
|-- README.md
|-- AGENTS.md
|-- .gitignore
|-- document/
|-- project/
|   |-- rtl/
|   |-- ip/                    optional
|   |-- sdc/
|   |-- par/
|   |   |-- <project-name>.xpr|.pds|.al   one canonical depth-0 launcher
|   |   `-- <project-name>.* native databases and reports
|   `-- script/
|       |-- run.bat
|       |-- setting.bat
|       |-- src_list.txt
|       `-- one confirmed vendor Tcl/CLI flow
|-- simulation/
|   |-- tb/
|   |   `-- case/
|   |-- work/                  generated by the formal simulator BAT
|   `-- script/
|       |-- run.bat
|       |-- setting.txt
|       |-- src_list.txt
|       `-- vsim.do
|-- linter/
|   |-- lint_bb/               optional
|   `-- script/
|       |-- run.bat
|       `-- lint_list.txt
|-- release/
|   |-- golden/                optional
|   `-- output/
`-- codex_out/                 Codex diagnostics/review only; ignored
```

## One-click contract

The user double-clicks one of the three `run.bat` files. Each wrapper anchors itself with `%~dp0`, verifies the configured deterministic lists and preflight facts, invokes only the selected native vendor adapter, preserves the exit code, and prints a truthful result. Build state, databases, logs, and reports stay under `project/par`; formal ModelSim/Questa export, work libraries, logs, and waves stay under `simulation/work`. Codex-created experiments and review packets stay under `codex_out`. A successful diagnostic simulation reports `DIAGNOSTIC_ONLY`, not `SIMULATION_PASS`.

The canonical vendor launcher is a direct file at `project/par/<project-name>.xpr`, `.pds`, or `.al`. Same-name tool databases are direct siblings. A newly generated `project/par/vivado_project/<name>.xpr`, `project/par/build/<name>.xpr`, or randomized project container fails normalized layout acceptance even though it is technically below `par`.

Formal BAT files configure only a tool root or vendor environment, prepend required directories to their current process PATH, verify canonical commands, and invoke command names. Do not embed one machine's absolute `vivado.bat`, `vsim.exe`, or equivalent executable path; do not modify user or system PATH.

Visible script roots are entry-point surfaces. `project/script` contains `run.bat`, `setting.bat`, `src_list.txt`, and one confirmed vendor Tcl/CLI flow. `simulation/script` contains exactly `run.bat`, `setting.txt`, `src_list.txt`, and `vsim.do`. Generated exports, `modelsim.ini`, `.Xil`, work libraries, logs, and waves stay under `simulation/work`. The formal desktop runtime does not depend on Codex-private PowerShell.

`project/script/src_list.txt` contains product HDL, `+incdir+` entries, and selected official IP configuration paths. `simulation/script/src_list.txt` contains the canonical simulation compile order for project RTL, explicit simulation models, and TB sources; official vendor export may supply managed IP models. `linter/script/lint_list.txt` contains lintable HDL. Lines are stable, unique, and verified to exist. Dependency-sensitive package/VHDL projects use optional authoritative order files under `document/`; ordering is never guessed.

Before generating output products from copied or legacy XCI/IDF/IPC, verify that its source view belongs to the current checkout. Otherwise stage/import it under the current project output or recreate it with the installed same-version official tool. Internet examples are documentation, not product configuration files.

Build BAT defaults to `compile`; simulation BAT defaults to GUI and supports `batch` for automated smoke. ModelSim/Questa evidence requires real compile, load/elaboration, and run stages. On Windows, inspect the emitted Xilinx export files rather than assuming `compile.bat`: a generated `.sh + compile.do` flow can be wrapped by BAT/DO after creating its required parent library and enforcing nonzero compile exits.

Passing Codex diagnostic jobs may remove large disposable caches while retaining commands, versions, logs, reports, result JSON, and proof packets. Failed diagnostics retain their reproducer. Cleaning formal `project/par` or `simulation/work` requires an explicit clean action and exact path validation; generic Codex cleanup remains restricted below `codex_out`.
