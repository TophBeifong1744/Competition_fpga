## 12. Vivado／Vitis／MCP 与其他专业任务

### 12.1 不复制上游完整工程手册

上游覆盖 RTL、IP、周期行为、CDC／时序、工程脚本、相关固件和板级准备，外层只提供本次明确范围及申请能力层级。[U1](sources.md)、[U2](sources.md)

诊断只证明诊断范围；功能仿真不签 CDC／STA；综合不等于实现时序；部署准备不等于实板通过。算法参考、模块、子系统和系统按真实依赖推进，不要求全部严格串行。（用户指导中概括的项目基线；未读取私有原报告）

### 12.2 适配已有 Vivado MCP，而非假定即插即用

首次接入需要验证：

- MCP 实际可执行哪些操作，有哪些权限／环境限制。
- 是否能定位正确工程、工具版本、器件和源码。
- 是否返回真实命令／状态、报告位置和必要失败信息。
- 是否会修改工程数据库、IP 配置、全局库或其他任务目录。
- 如何确保同一可写工程／运行目录串行占用。

上游要求验证正式入口时，直接运行内部命令或替代仿真器不能证明那个正式入口有效。现有嵌套工程按第 7 节登记映射并验证适配；未经授权不为了模板自动搬迁到新目录。路径映射本身不能替代上游所需的真实入口验证。[U1](sources.md)、[U5](sources.md)

不虚构 Vitis 自动化：只使用当前实际存在的脚本或工具。硬件描述变化后，核对平台／BSP／驱动及 bit、XSA、ELF 等配套关系；不把软件编译成功当作已部署正确硬件。（用户指导中概括的项目基线；未读取私有原报告）

### 12.3 便宜检查与昂贵检查分离

日常可自动执行范围内的语法、模型小测试、接口一致性和必要单元检查。完整综合、实现、重回归、长稳和板测按影响与阶段合同触发，不每次 push 全跑。

没有 EDA 环境的 CI 可以验证包、脚本、结构或可用测试，但不能宣称 FPGA 工程已通过。首次工具入口、缓存失效或高影响变更必须真实验证。

模型同一任务选择一个主要黄金参考；另一语言／工具只承担确有价值的独立核对，不默认双份完整重写。真实输入受损先修数据交付，不能调算法掩盖输入问题。（用户指导中概括的项目基线；未读取私有原报告）

### 12.4 自动返修有界

沿用上游同一问题的返修上限：最多三轮自动修复／复审；首次无进展时重新核查根因，连续两轮无进展或三轮后仍有阻断则停止自动扩展。[U1](sources.md)

外层不能通过换任务名、换 Agent、换模型／思考强度、重开 PR 或重新进入内层来重置同一问题的计数。新的问题与新范围需要明确区分，不以改写描述假装新增证据。

## 17. 全员安装、版本锁定与首次接入

### 17.1 安装内容

每位成员安装：外层 `fpga-team-workflow`、内层 `run-fpga-workflow` 及其配套角色／参考文件，以及本人任务需要的实际工具。

上游参考版本的安装脚本会部署 Skill 目录和 13 个 Agent TOML 配置，不是仅复制一份 `SKILL.md`。[U3](sources.md) 默认不强制安装全部 EDA 工具，但工程运行前必须确认实际可用环境。

建议：通用 Skill 安装一份经验证的用户级副本；项目保留配置和版本锁。确需项目级安装时选择一个明确作用域，避免同名用户级／项目级 Skill 并存而加载不确定版本。官方说明，同名 Skill 不会自动合并，必须在实际客户端核对发现路径。[O1](sources.md)

上游安装脚本的作用域和路径以其当前锁定版本为准。不要未经核查启用覆盖选项，也不把其他成员的全局 `AGENTS.md`、角色或工具配置整体替换成模板。

### 17.2 首次接入一次做完

核对 Git／Codex／PowerShell 及实际工具 → 安装指定版本 → 验证 Skill 与角色 → 核实已有项目映射或新项目布局 → 核对本人可用模型／effort 和角色配置来源 → 用只读案例确认模式／加载来源 → 在本人能力范围验证工具入口与输入归属 → 保存简短接入记录。

模型接入检查不要求购买订阅或运行全部候选模型；只确认真实可用性与必要能力。暂不能读取实际设置时记录未知，不能把示例模型表当作本机可用清单。

不同成员允许有不同绝对路径和工具权限；共享的是规范、目标器件与对应构建要求。不能把某成员的 Windows 盘符写成通用 Skill 常量。

### 17.3 依赖锁定

锁定：外层发布版本与来源、上游版本与准确提交、桥接接口版本、适用的安装范围／客户端验证记录，以及团队 `model_policy` 的版本与内容身份。工程工具版本保存在项目工程配置中。

模型 ID 或服务别名不等于服务端权重已被本地永久冻结；有实际返回的解析版本时按可观测范围记录，不虚构固定快照。成员端实际可用性与正在使用的配置另记，不通过修改锁文件追改旧运行事实。

本文核对的上游参考版本为 `0.4.0`，读取的固定提交为：

```text
e40fd8000b526b72ba80373127bf5fd6e5f8dc28
```

这是制作时的参考基线，不是“永远最新”的声明。实现者需用该版本核对本地安装与接口；若改用其他版本，必须走第 20 节维护验证，不擅自追踪移动 `main`。

读取相容性问题可继续只读诊断；缺少必须工程依赖或已确认不兼容时，不伪装按指定规则完成正式接受。
