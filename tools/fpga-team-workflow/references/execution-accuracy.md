# 文件、路径与读取防错

适用于实际文件修改、批处理和交付。核心不是增加复核轮次，而是让错误目标在写入前被拒绝；简单编辑可用已有工具检查，不要求另建脚本或记录库。

## 一次确定输入和修改边界

- 沿原派单提取目标、准确输入、允许修改范围、完成判据、停止条件。已有明确合同直接引用，不重复抄录全部历史。
- 已存在路径从实际目录枚举、固定 Git 树或已核来源索引取得，选中后作为变量/结构化参数复用。必要输入缺失时列精确缺件，不从摘要重建内容、不尝试猜相似名称。新文件名来自本批约定，先验证父目录与重名状态。
- 修改前记录简短的允许文件清单，或确有生成需要的独占输出根；区分只读原件、可写候选和运行输出。新增目标应有本批内的具体原因并检查占用；超任务范围才需要新授权。
- 必要读取被截断、分页未结束、附件未打开时，明确哪些内容未读，并定向补读后再依赖它作决定。不把路径存在、标题或摘要当作已读正文。优先小范围检索/结构化摘取，避免反复输出过长内容。

## 写入前检查，失败不扩大动作

- 复用现有维护器、补丁工具和路径检查。脚本对目标解析后的路径/父目录核验允许范围；对已有源文件核对本批基线，遇到意外链接、越界、重名或漂移就停止受影响写入。路径参数使用各工具正确的字面值/引用方式，不拼接未经处理的 shell 命令。
- 文本替换先检查目标存在且匹配数量等于预期；结构化文件先检查键、类型及数量，再改字段。断言失败不退回全局替换或自动创建缺失输入。补丁上下文失败后重读实际目标，不用旧偏移继续写。
- 重命名、移动、删除不作为普通修复的顺带动作；确为本次任务所需且已获授权时，先明确源/目标与相关引用，再检查冲突。保留旧失败、未提交及未跟踪材料；不以复制整套工程或覆盖原件防错。
- 多文件操作不能保证原子性时，保留受控原字节和逐项结果，失败后报告已写/未写范围。不把部分成功称为整批成功，也不盲目重放已完成动作。

## 最小收尾与根因修复

- 以开工基线核本批实际差异：修改文件是否在允许范围，约定入口是否存在且指向正确版本，必需交付是否齐全。共享目录已有脏文件不归为本批改动，不删除、不替其他任务验收。
- 只运行受影响入口与核心检查；同版适用结果复用。只改文稿时检查链接、版本和代表性规则冲突，不追加 FPGA 仿真矩阵或全仓扫描。
- 路径、封装、编码、解析与测试资产失败先按实际首因分类，不能借此修改正确产品。相同低级错误复现时修公共入口或复用现成脚本；保留第一次失败和适用停止计数，不无限试错或只追加“小心”提示。
- 完成回报说明实际变化、验证及未完成项。哈希/清单通过只证明对应身份，不证明功能或成员接受。

## 更新不打断在途任务

新版本先形成可核对分发包；活动任务保留原版本与原授权。本机共享安装目录被在途任务使用时，先提供安装预览和待切换包，在安全断点重新核对后安装；不发会覆盖执行指令的催更消息。新任务按已声明的新规则执行，未实际安装/重载的聊天不得宣称已升级。各项目成员、工作目录及 Notion/Space/GitHub 入口从本项目配置读取。
