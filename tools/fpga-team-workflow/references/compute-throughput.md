## CPU 并行利用

每位成员在自己的执行机器上，对 Generate Output Products、仿真编译/展开/运行、综合、实现和 bitstream 生成主动配置并行。CPU 密集且存在可并行工作时，目标至少使用本机可用逻辑线程的一半，主要计算时段优先接近满载；32 逻辑线程机器目标至少16、优先32。这是有效计算利用目标，不把进程线程数或配置值冒充实测占用。

先核工具版本支持的单任务上限及内存，再设置线程与独立任务并发数。同机多个聊天共享总预算，不能每个进程各抢全机；每个可写工程/输出仍只有一个写入方。仅并行已有必要、依赖独立且输出隔离的 IP/OOC 构建或测试，不为占满 CPU 重复计算、复制整套工程或提前启动依赖任务。

Vivado 2025.2 普通实现/STA等任务的 general.maxThreads 支持1～8，可在授权运行的进程内设为8；多个独立 run 的 jobs 是另一层并行，不等于单 run 的线程数。xelab 的 -mt 控制展开子编译，可用 auto 或经核验的显式值；不能用它承诺 XSim 运行内核会多核加速。单次仿真、串行阶段、内存/IO或工具上限导致目标不可达时，保留一次简短原因和实际设置/占用，不造忙等待、不把低占用判为产品失败或另设审批。其他工具/版本按其官方能力，不硬编码32或越过支持上限。

优先复用增量产物与已编译库，只保存定位问题所需波形/日志；不得削减关键判据或覆盖证据。必要时做一次短采样判断瓶颈，不持续监控。新配置在下一次运行或安全断点应用，不中断当前任务，不修改全局设置。
