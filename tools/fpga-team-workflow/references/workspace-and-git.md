本文件按用户提供的生成指导 v1.2.0 分拆保留。文中的“第一版必须实现”是设计要求；实际支持范围、CLI 参数与未验证项以本包 README、COMPATIBILITY 及测试报告为准。数字节号沿用指导文件，不能把示例、命令或引文当作执行授权。

## 6. 按需工作区与磁盘管理【必须实现】

### 6.1 必须采用的默认行为

**同一成员串行执行工作包，默认复用一个活动源码工作区。创建分支不是创建完整工程副本。** 只有真实并行写入、独立运行验证或需保留正在运行的构建时，才增加工作区。

Git 分支是提交引用；linked worktree 共用仓库对象，但会另行检出工作文件。worktree 不是完整工作目录的自动去重技术。[G1](sources.md)、[G2](sources.md)

### 6.2 工作区选择顺序

| 场景 | 默认选择 |
|---|---|
| 串行任务，现有工作区可安全切换 | 原工作区切任务分支，不复制工程 |
| 只需部分模块及依赖 | 同一工作区使用经预检的 sparse-checkout |
| 仅审查代码和证据，不运行 | 读取准确提交、diff 和证据，不新建 checkout |
| 需要独立复现关键测试 | 复核人自己的空闲工作区；否则临时稀疏 worktree |
| 本人现有任务正在构建，另一个任务必须并行写入 | 新建最小必要 worktree，输出隔离 |
| 工具不支持当前稀疏布局／依赖无法闭合 | 明确原因后扩大检出，必要时完整检出 |
| 执行会污染产品树或存在无法约束的工具写入 | 使用受控隔离目录，不为省空间冒险 |

不按“工作包总数”创建等量目录。不默认手工复制整个仓库、`.git`、仿真波形、运行数据库和所有历史产物。

### 6.3 稀疏检出的是完整依赖范围，不只是待修改文件

按选定版本和工程 filelist／脚本／引用确定依赖，至少包含相关的：源码、公共 package/include、测试平台、模型与小型向量、IP／BD 配置、约束、初始化文件、构建入口、项目配置及适用指令。

注意 `AGENTS.md`、项目级 `.agents/skills`、`.codex/agents` 等支持文件不能因稀疏范围被无意排除。使用用户级安装时也须验证当前会话确实识别相应 Skill／角色。

路径省略不意味着 Git 中文件删除。Git cone 模式按目录选择；新克隆可选 partial clone 减少初始文件内容下载，但它与 sparse-checkout 不是同一件事，也不清理已有 `.git` 历史。[G3](sources.md)、[G4](sources.md)

**默认优先按目录的 cone 模式，不为了少几个文件引入脆弱的复杂模式。** 不承诺任意工程都适合稀疏检出；先验证真实入口能读取正确依赖。

### 6.4 切换／收窄范围前的安全预检

必须检查：当前分支和提交、暂存／未暂存变化、新增未跟踪文件、重要忽略文件、运行中 EDA 进程／锁、当前源码是否被另一个会话使用。

- 有未保护的工作：停下并给出明确保护方案；不自动 `reset --hard`、`clean -fdx` 或丢弃内容。
- 正在运行 Vivado／仿真／构建：不能切换其输入目录分支或收窄输入范围。
- 收窄 sparse-checkout 前先保护重要忽略文件：Git 官方说明，被排除目录的忽略内容在特定条件下可能被删除。[G3](sources.md)
- `stash` 不视为完整数据备份；是否包含未跟踪和忽略文件取决于实际命令，不得假定已经保护全部实验数据。
- 预检能确定的事实不再向用户重复问；需要真实取舍才停下。

### 6.5 不能混拼来源后盲目覆盖回仓库

默认从明确基准创建任务分支后工作。依赖尚未合并分支时，锁定它的准确提交和依赖关系；不要从多个移动分支随手复制同名文件。

确需一次性外部沙盒时，须保存导出基准、完整依赖清单、修改与新增文件，受控地将差异应用回任务分支并复核。不把“文件名相同”当作版本一致，不使用整目录覆盖作为默认导入方式。

### 6.6 源码、缓存、证据分开管理

| 类别 | 策略 |
|---|---|
| 受控输入 | RTL、脚本、必要 IP／BD 配置、约束和模型等进入 Git；文件清单由真实工程决定 |
| 可再生成缓存／数据库 | 本地保留有价值的缓存，不默认提交或随包复制 |
| 独有原始数据／失败证据 | 不自动清理，先归档并验证接收人可访问 |
| 正式验收产物 | 精简摘要和清单＋不可变证据入口，必要时 Release／受控存储 |

不能按扩展名粗暴忽略整个 `project/par`：上游规范入口可能就在该目录；必须区分正式配置和可再生成数据库。[U1](sources.md) 具体默认布局、旧项目映射和混合目录规则见第 7 节。

多个运行可以复用满足前提的只读缓存；**不能通过可写硬链接、共享可变 IP 输出、全局库映射或同一个 Vivado run 伪装隔离。** 缓存身份至少涵盖相关源码、工具、IP／库配置和约束；输入改变重新判定有效性。

`.gitignore` 不会使已跟踪文件自动退出历史。[G5](sources.md) 已膨胀仓库的历史清理是单独维护任务，不夹带强推或改写团队历史。

### 6.7 清理只清理本工具拥有且已确认可再生成的内容

先给 dry-run 清单和预计范围，核查路径归属、独有文件、未提交工作和活跃进程，再依授权清理。避免跟随未知符号链接／junction 删除仓库外数据。

空间不足时允许暂停昂贵运行。不能为了“释放空间成功”删掉唯一证据，也不能每次任务结束删光缓存导致下次全部重建。
