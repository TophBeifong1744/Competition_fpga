## 4. 不能直接使用厂商 XDC 的原因

厂商 XDC 是多个示例工程的合集，不是 SoundSight 的约束文件：

1. 同名 UART 端口在不同示例段落中映射到不同引脚。
2. LCD 与 HDMI 示例复用了 R19、P20 等引脚。
3. 摄像头、以太网、音频等互斥或无关外设同时存在。
4. 文件没有表达 SoundSight 的四路采集接口和外部时序。

因此，正式约束只能在实物和采集器件确认后，于 `vivado/constraints/` 新建专用 XDC，并只保留实际启用的端口、时钟、IOSTANDARD 与输入/输出延迟。

## 5. 四路同步采集仍缺少的事实

| 字段 | 必须获得的值 | 当前状态 |
|---|---|---|
| 采集器件 | 厂商、完整型号、模块版本、数据手册 | 待提供 |
| 通道数 | 单器件/多器件如何组成 4 路 | 待提供 |
| 物理接口 | PDM、TDM/I2S、并行 ADC 或其他 | 待确认 |
| 共享时钟 | 时钟源、主从关系、频率、占空比、采样边沿 | 待确认 |
| 帧格式 | 通道槽位、字长、有效位、符号、对齐方式 | 待确认 |
| IO 电平 | 外设 VIO、是否 5 V 容忍、是否需电平转换 | 待测/待查 |
| PL 引脚 | 连接器针脚、FPGA 管脚、Bank、冲突外设 | 待选取 |
| 固定延迟 | 四通道链路是否同构、怎样测量和校准 | 待设计 |
| 输出链路 | ES8388、外接 DAC 或仅先导出文件 | 待决定 |
| 长录音导出 | DDR 缓冲后走 SD 或网络 | 待决定 |

板载 ES8388 不等于四路同步 ADC。只有在实际器件证明具备四个同步输入通道、PL 可取得各通道原始样本且时序可验证时，才能把它纳入采集方案。
