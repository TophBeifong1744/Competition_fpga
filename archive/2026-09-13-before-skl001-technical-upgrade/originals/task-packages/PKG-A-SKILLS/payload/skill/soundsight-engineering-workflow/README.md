# soundsight-engineering-workflow

候选版本：0.2.0。这是从真实协作失败中提炼的 FPGA/嵌入式工程工作流，不是 SoundSight 项目状态台账，也不是自动板测或自动合并工具。未经项目指定复核人批准，不替换现有活动版本。

## 适用范围和用法

适合需要并行开发、早期诊断、模型/RTL/时序/板测分层验证、完整包交接和可复现发布的团队。不限麦克风、Zynq、PYNQ或特定人数；单人项目可使用证据和复现部分，但不能把自己的自检称为独立复核。

把本目录交给支持 Markdown 指令的智能体，明确要求读取 [SKILL.md](SKILL.md)；已被本机技能加载器发现时可使用 `$soundsight-engineering-workflow`。仓库含 `skill/` 不代表已经自动安装，不要求陌生队伍先有 SoundSight 的目录结构。

最小请求示例：

```text
使用 soundsight-engineering-workflow。我们在做 FPGA 温度采集器，读取本目录 SKILL.md。
输入是版本化数据合同、当前测试报告和项目权限说明。只审查，不改源码。
分别返回可继续的开发、待批准的集成、已证明的能力和发布状态，列出证据及下一步。
```

提供：目标与授权路径、现行规则、数据/接口版本和暂定项、实际产物与测试/复核记录。缺项应指出具体影响，不要求补齐所有硬件材料才处理一个软件任务。记录只用 [必要模板](references/record-templates.md)；不必每次填完整套表。

## 输出与停止条件

一次使用应得到可执行的下一步、局部阻断原因、四类证据状态、允许/禁止的结论、复现入口及准确版本交接。仅当影响当前动作的安全、权限、接口或事实缺失时暂停相关动作；不将验收清单变为所有代码的串行开工许可。

典型边界：暂定接口可用于离线原型，不用于猜针脚接板；短实录可供诊断，不等于长稳/精度验收；算法包可用预算评估有限准入，不必先有最终布局布线，但不能据此承诺实时；批准研究归档不等于批准系统接入。复杂技术包由当前指定的技术复核人审查，作者不自审自合。

## 失败和观察如何形成规则

| 实际观察 | 提炼的可复用规则 |
|---|---|
| v0 以最早未通过门为总阻断，和后来的暂定接口并行开发安排冲突 | 按具体动作判断依赖；分开开发、集成、验收和发布 |
| 早期只确认器件族，后来完整 part、四路诊断和限定复核已到件 | 通用指令不写死当前进度；历史样例标日期/版本，当前状态读最新证据 |
| 短录音可解析，但没有准确几何/声源真值；FFT限定覆盖并非全链 | 诊断、数值验证和正式性能结论分别登记，不越级传递 PASS |
| 28页 AMD 指南曾与3页 FAQ混淆；用户纠正后核对原页 | 引用明确文件/页/版本；保留可见纠正和复验，不重写旧记录 |
| 系统校验器在缺 PyYAML 的解释器中失败 | 环境失败与被测功能失败分开，记录实际解释器和依赖 |
| 发布成功仍可能遗漏被忽略的原始输入和日志 | 按批准批次核对真实共享目录和远端、材料去向及恢复方式 |

来源为 SoundSight 的真实材料和用户可见纠正；不是把所有列出的风险都说成已发生硬件故障。项目的角色、H1/H2/H3名称、日期和暂缓项由项目规则提供，不能复制为所有竞赛的强制组织方式。

## 验证效果与边界

v0 曾通过结构检查和旧 M0 场景测试；这是历史测试，不证明0.2.0，也不再作为阻止独立开发的依据。2026-09-13本次实际执行了三个独立评估任务：v0/0.2.0分别回答同一个虚构温度采集网关的四项请求，0.2.0另处理当前SoundSight的只读状态交接。评估任务仅得到Skill、最小输入和业务请求，没有收到作者验收判据或其他评估答案。

| 实际使用测试 | 观察到的效果 | 限制 |
|---|---|---|
| 0.2.0非声学项目迁移 | 允许暂定格式下的parser/TB；禁止未知电压针脚接板；支持预算驱动的有限原型评审；短数据保留断点做诊断；拦截r4归档批准冒充r5合入和虚构发布收尾 | 作者逐项检查8个行为判据，均满足；虚构输入，不是真实第二块板或另一团队生产试用 |
| 0.2.0真实项目状态交接 | 识别H1/首批H2已完成，9/13提前阶段进展限定通过；不重派旧FFT/录音，不把诊断、reference25或内部时序升级为整机；不强制PYNQ，不给C加任务 | 作者检查6项判据均满足；仅读取实际现行材料，不重跑硬件、算法或原验收 |
| v0同场景对照 | 旧版评估者也允许包内parser/TB与短输入诊断、拦截未审r5；未观察到该样例触发全局停工 | 不宣称0.2.0提升了成功率；此次修订消除明确文本冲突，但不是证明旧版在所有场景必然失败 |

同日系统quick_validate通过。本包清单验证器11个独立字节夹具测试通过，包括篡改/缺件/多件/换行变化、非法路径/哈希和CLI失败后恢复复验；这些是交付完整性检查，不是智能体行为测试。输入哈希、原始可见答复、判据与命令分别保存在PKG-A-SKILLS交付证据中；测试结束后核心SKILL.md及模板保持受测字节，README只补入本摘要。

没有B人工批准、真实跨板运行或新硬件验证。若另一个团队使用，仍须提供自己的授权和有效证据；本次少量案例不构成稳定成功率或普遍可靠性保证。

本 Skill 的效果只能由实际产出证明：是否允许正确的独立开发、拒绝越界硬件/发布、保留失败和证据等级、能否在第二种项目使用同一核心指令。`quick_validate.py` 只验证结构，不证明以上决策，也不证明任何 FPGA 或 PYNQ 实板通过。

比赛提交保留本目录和根 `skill/README.md` 索引，文件路径用英文名称；必要的试验输入、输出和复用记录纳入获准报告/证据附件，检查匿名/隐私与再分发许可。不复制供应商工程、完整官方 PDF 或私人聊天。采用其他目录布局时给出映射。

报告写“风险/失败 → 可见提示和回答 → 人工纠正及修改理由 → 实际复测 → 适用边界”。只记录用户可见内容，隐藏思维链、系统/开发者提示不属于提交物。测试作者的评估也不是 B 的技术批准。
