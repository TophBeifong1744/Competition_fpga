## 3. 两项完整交付与本队亮点

### SKL-001：可迁移的工程协作与证据判定

唯一活动目标：`skill/soundsight-engineering-workflow/`。A沿既有工程协作Skill任务继续，B复核。项目人数、麦数、路径、日期、器件与PS后端从输入读取，不固化在通用规则中。

完整包至少包含：可触发的SKILL.md、竞赛README、最小记录模板、实际案例与一个非声学迁移案例、原始提示/输出和修正记录、判据及复现入口、版本/许可/来源、交付清单与复核入口。已有材料够用就引用固定版本，不复制整个SoundSight工程。

本队主打贡献：**区分“可以继续开发”与“可以宣称通过”**。保留三交接点的高效协作，又能阻止仿真冒充板测、旧SHA批准新内容、收到包冒充复核、非阻塞缺证拖停无关工作。它应给出下一条能做的具体动作，而不是只输出一串BLOCKED。

B的最小行为验收（团队自设，不是官方规定数量）：

1. 同一套输入分别运行旧版和候选：一个固定版本真实项目案例、一个非声学嵌入式案例；评估上下文隔离，不向使用者提供参考答案或评分表。
2. 至少覆盖四种判别：仿真但无板测；批准SHA后内容变更；非阻塞补证不齐但可写代码；电源/针脚明确冲突需停止相关接板。
3. 新版不得出现越级PASS、越权硬件操作或误停全部独立工作；正常例须产生可执行下一步。记录逐项成功/失败、人工纠正次数；旧版已通过的可用输入保持通过。
4. 有前后差异才报告改善，无提升照实写；一次隔离案例不能宣称适用所有嵌入式项目。清单哈希只证完整性，不证明物理来源或人工批准。

### SKL-002：可配置的PYNQ数据通路验证

唯一活动目标：`skill/pynq-overlay-dma-validation/`。A沿既有PYNQ Skill任务开发；B提供独立golden、验收输入和复核。A负责真实板级准入与驱动适配，B不代签未接触板卡的实测。

完整包至少包含：SKILL.md、竞赛README、profile/会话合同及例子、可运行检查器与测试、板级操作单、源数据/输出/golden及证据报告、失败/修正轨迹、迁移说明、许可/版本与复核入口。把平台配置、实际驱动适配器、验证核心分开；不把SoundSight的板名、通道数或寄存器地址写死。

本队主打贡献：**面向真实接收链的故障诊断与安全收尾**，辅以精确golden比对。重点验证缓存新旧数据、超时/部分启动后缓冲区归属、停止未确认时不释放、错误profile拒绝、整数比较不因浮点转换误PASS。可复用已有离线实现，不为亮点扩做SG/cyclic/中断全功能或通用新IP。

B的最小验收（团队自设）：

1. 在干净环境复跑准确提交中的全部测试；作者报告50项仅是本次基线，后续按实际清单计数，不以凑数量验收。结构检查不能替代行为测试。
2. 至少两套不同题目/IP/数据格式的profile，在不改验证核心的情况下运行；用普通流处理样例作迁移，不新增四麦声学模拟。模拟第二板只能证明配置迁移，不能称两块板实测。
3. 保留正常S2MM接收及匹配设计才可做的loopback；故障至少覆盖artifact不匹配、长度/地址对齐、缓存陈旧、超时/停止未确认、短输出、golden不符（含大整数）。关键故障不得误PASS，不得不明归属释放DMA内存。
4. 真实PYNQ路线单列：A先核实实际镜像/板支持、同构建bit/HWH、分配器/缓存/实际驱动语义和停止机制，再在已匹配硬件上跑接收/golden/重复运行。使用实际板卡现有工程，不臆造MM2S或有副作用的寄存器访问。
5. 实测报告记录字节数、次数、错误、计时方法、软件开销和实际端到端吞吐/延迟；FPGA资源和时序引用同构建原报告。软件mock耗时不得当硬件加速，Skill优化和PL加速分别比较。

PYNQ若未能准入，继续交可复用离线工具、失败记录和明确未测范围；已有Vitis采集/声学主线照常推进。**这只能验收离线Skill范围，不能声称真实PYNQ项或加分证据已完成**。Vitis/PetaLinux替代不等于PYNQ验证；届时公开登记加分风险，不用假板测补齐。

## 4. 制作流程、交付位置与分工

流程：固定实际失败和输入 → 写场景/边界/可观察判据 → 改最小流程或脚本 → 同输入前后对照与故障测试 → 陌生上下文试用 → 整理可见纠错和效果 → 工作执行推送完整待审包 → B按准确SHA复核 → 批准范围合入/在新入口验证/发布核对。先跑已有案例再补文档，不开长篇调研前置。

- A工程协作Skill任务只写SKL-001候选；A PYNQ任务只写SKL-002；A工作执行统一处理根索引、任务分支与交付提示。两项不得同时覆盖`skill/README.md`。旧候选中的根索引合入前须对当前计划重新对齐，不能覆盖最新状态。
- 继续使用已有`task-packages/PKG-A-SKILLS/`包的SKL-001候选，不搬动或修改它的已签清单。SKL-002现在以活动目录为唯一在做源，完成后由工作执行按准确版本收为同包中的独立完整交付，例如`deliveries/skl-002-v1/`，集中说明/清单/复核及固定源码来源，不保持两份并行开发源码。
- 两项可分别完整交付、分别复核；一个已齐不等另一个。B审A，不审批每个离线实验；这不是新增H4。优先复用B既有golden，缺独立参考时标明只测软件一致性。
- B先完成9/18算法H3关键路径；Skill案例标准可在现有golden上顺手明确，独立Skill复测集中安排在完整候选到件后，不要求同时另起一套算法工程。
- C无新增采录、测试、报告、Skill或复核任务。复用原两个Skill聊天，不新建重复任务；可转发说明见[阶段派工入口](phases/2026-09-13-to-10-01/dispatch.md)。写了提示词不等于已送达或成员已接收。

每项交付携带README、入口/依赖、输入输出、失败条件、实际效果、来源/许可、可见纠错、测试命令与日志、准确源码/配置/输入版本，以及待测项。记录模型/工具版本；只有工具实际提供时才记token/耗时，不估填。原始日志保留但脱敏，不上传密钥、学校标识或他人未授权数据。
