## 每次都做的五件事

2026-09-12补充：[四类聊天工作流](team-workflow.md)规定每次复核通过即按范围合入、推送和安全去重；本页是每阶段集中汇总，不把例行合入拖到检查日。历史流程与此冲突时以新约定为准。

每批推送后的[本地/远端 main 对齐与遗漏材料检查](team-workflow.md#batch-closeout)是独立必做收尾。阶段汇总复用各批次记录，核对有无尚未完成的同步或材料处置；不因为主线已推送就将这些项默认为完成。

1. **确认范围。** 固定验收输入版本，分别列已批准、仅作者自测、待审和未完成。阶段检查通过不等于阶段内所有任务都获技术批准。
2. **归位集成。** 获准且适合复用的源码进入活动目录：HDL→rtl/，测试→tb/，文件清单和回归入口→sim/，其他层进入对应model/ps/vivado等目录。仅归档、仅诊断或尚不具备接口依据的成果不强搬，逐项写明未接入原因与下一步。不得把整个待审分支顺带合入。
3. **在新位置验证。** 使用活动目录源码运行与变更相称的测试，而不是只引用原任务包旧PASS。记录实际命令、输入版本、输出和失败；功能仿真、综合、时序、BD和板测分开。运行入口不得偷用另一份同名旧源码。
4. **集中归档。** 在deliverables/phase-YYYY-MM-DD/保存本阶段已验收快照、清单和CLOSEOUT.md。冻结原件不覆盖；延后补做的集成用注明日期的补充记录。task-packages保留历史交付，不作为与rtl/并行修改的第二份活动源码。
5. **发布并说明。** 更新当前状态/任务台账/验收日历的收尾入口，检查提交范围并按授权发布；说明已接入的路径、实际验证、未接入项、归档位置、发布提交。清理临时输出；任务分支/副本只有在已完成、无未保护独有改动且删除获授权时清理，长期分支和进行中任务保留。

## 状态必须分开

| 状态 | 含义 |
| --- | --- |
| 阶段检查通过 | 本检查点约定范围通过，不自动批准所有包 |
| 已批准并归档 | 有准确版本批准和保存，但可能尚未接入活动目录 |
| 活动目录/模块库集成完成 | 文件归位、入口可运行、对应回归完成 |
| 实际系统集成完成 | 真正接到系统顶层/BD/PS且有对应验证，不能由文件归位推定 |
| 阶段收尾完成或部分完成 | 上述各项处理结果已列清；有阻塞就保留部分完成，不能藏在“已归档”里 |

精细电气/外部时序/历史加载补证按暂缓规则执行；不能用本收尾规则重新要求全套仪器证据，也不能把未测项改为通过。不为了填目录引入空模块、未审代码、猜测接线或新的算法实现。

## CLOSEOUT.md最小内容

- 验收日期、补做日期、固定输入提交与批准依据。
- 原任务包文件→活动文件的映射；必要的换行/路径变化说明。
- 已实际运行的命令及结果，明确未运行的综合/时序/板测等。
- 未接入清单、原因、负责人和下一步；无变化也明确写“本阶段无新增获准源码”，不能省略。
- 快照/清单位置与发布提交；在最后一次提交前可通过该记录的Git历史定位，发布后向用户报确切SHA。
- 各批次本地/远端 main 对齐结果、未跟踪/忽略有用材料的处理去向；仍待处理者注明负责人，不倒填旧快照。

这是一张收尾表，不要求每个小实验单独交包；完整包交付、复核人合入和H1/H2/H3规则继续执行。
