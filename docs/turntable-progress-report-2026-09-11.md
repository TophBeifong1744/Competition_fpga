## 4. 方向计算之后的控制链路

当前[架构说明](architecture.md)规划如下，整条机械链路尚未实现验证：

```text
声源方向 + 置信度 + 音频帧时间戳
    ↓
PS：坐标换算、置信度门控、角度平滑、死区与速度规划
    ↓
驱动接口：STEP/DIR、PWM或位置命令，具体方式待执行器确定
    ↓
电机、传动与转台
    ↓
编码器 / 零位 / 限位反馈 → PS位置闭环及故障停止
```

[工程流程第5节](engineering-flow.md)中已命名三个规划模块：

- `tracking_controller`：PS侧的等待、获取、跟踪、保持与故障状态机。
- `motor_if`：输出电机脉冲、方向、使能或位置命令。
- `position_if`：读取编码器、零位、限位和驱动故障。

本轮在 `rtl/`、`ps/`、`vivado/` 与 `task-packages/` 的当前源码/文件名检索中，未找到转台控制器、电机接口等对应实现。检索排除了恢复副本和历史参考快照；该结果与任务台账的“暂缓、当前无转台开发任务”一致，不构成对仓库外所有文件或实体库存的盘点。

## 5. 与当前采集工程的关系

根据[当前状态](current-status.md)2026-09-11晚间记录，项目已有安静/人声各32000组、每段约0.667秒的四路真实短录音及文件导出成果，实际使用杜邦线。该状态不代表声源方向、波束效果或机械转向已经验收。

另外，[C的麦克风转接板](../hardware/microphone-adapter-decision.md)已经决定采用，并有工程适配记录。它是连接四路麦克风的阵列转接板，不是电机驱动板，不包含本报告所说的转台执行机构。采用 C 板不会自动启动机械转台任务。

现行 M7 启动条件仍是：先通过 M5 的真实录音对照证明核心声学收益，再明确需要朝向声源的实际载荷，例如摄像头或定向扬声器。目前未找到这项载荷的确定记录，也未找到满足条件后正式启动转台的任务记录。

这里的“后置”是项目范围与排期决定，不是说独立电机测试在技术上必须等声学算法完成。本报告不修改这一安排。

## 6. 后续真正启动时需要明确什么

以下仅列尚待决定的内容，不是现在新增的执行任务或采购单：

1. **转动对象**：只转摄像头/定向器件，还是带动麦克风阵列、开发板或整机；明确质量、尺寸、质心与惯量。
2. **运动需求**：单轴还是俯仰扩展、转角范围、允许响应时间、精度、线缆路线和安装空间。
3. **具体器件与接口**：据实际负载确定执行机构、驱动器、反馈、独立电源和可用IO，而不是先购买电机再倒推结构。
4. **实现及验证**：先以软件目标角独立验证机构，再接可信DOA；分别检查方向/零位、重复定位、限位/急停、声源消失及低置信度停止。

既有风险包括电机噪声与振动影响麦克风、转动过程姿态变化、音频帧与位置反馈时间不同步、坐标零位不一致以及线缆缠绕。它们是后续设计关注项，不是当前已发现的故障，也不阻塞无关采集工作。详细要求继续引用[采购指标第5.6节](../hardware/procurement-specifications.md)，本报告不另设风险待办或定期催办。

按[现有分工](team-tasks.md)，后续获准启动时由 A 负责控制与硬件，B 协助算法和声学判断，C 按明确操作单装配测试；`MECH-001`、`CTRL-001`、`SYS-003`当前仍暂缓。
