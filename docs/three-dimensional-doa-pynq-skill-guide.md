# 三维 DOA 与 PYNQ 通用 Skill 对齐指南

日期：2026-09-07。状态：3D-P5 已同步六麦第一轮软件预评审结果与材料包入口；已形成部分合成模型证据，完整 3D-G0 尚未通过，未形成三维 Overlay/DMA 或声学实板通过证据。本文仍为合同审查与测试指南，未修改接口、驱动或通用 Skill；V2 当前只做六麦预研。

## 1. 结论与当前边界

现有 `pynq-overlay-dma-validation` 可以继续验收 Overlay 身份、AXI4-Lite 合同、DMA 搬运、缓存一致性、golden 比对和性能/资源证据，不应加入 `azimuth`、`elevation`、方向向量或 SoundSight 数据格式等三维专用逻辑。三维升级应由 SoundSight 自己提供版本化接口说明、payload schema 和测试向量，再让通用 Skill 按外部合同执行。

2026-10-07 的交付目标仍是四麦二维 V1 的 M0～M6。本任务只在这份指南中准备验证矩阵、golden 数据结构和兼容性判据；不新增寄存器地址、位宽、DMA 布局或 PYNQ 驱动。V2 只输出方位角、俯仰角和指向声源的三维单位向量，不输出距离、三维位置或离地高度。

麦克风沿用用户此前选定的 IM73D122V01/PDM 路线，本轮不重新选型、不更换接口。该选择是既有路线背景；具体模块型号/版本、实物身份、供电电平、PDM 时钟与数据接线、同步及标定仍需对应证据，不能把用户选定或器件候选写成硬件已验收。六路候选的扩展核验继续在这条路线下进行，不据此推定现有模块已经支持或通过六路同步采集。

V2 当前只评审和模拟“水平正方形四麦＋上方一麦＋下方一麦”的六麦候选。非共面四麦只保留为背景及未来重新决策的备选，八麦暂缓；本轮不新增四麦三维模拟、四/六麦对比或六路抽四路实验，四麦三维产品不是本轮实施或验收依赖。六麦具体尺寸和硬件方案尚未冻结，也不构成采购授权。通道数与输出维度分别描述：理论上四路也可能用于非共面三维，六路数据本身同样不证明三维方向有效。

正式路线为 V1 保底门 → 3D-G0 六麦几何/浮点/预算 → 3D-GA 六路扩展采集准入 → 3D-G1 实录 → 3D-G2 定点/PL → 3D-G3 三维波束。3D-GA 必须位于 V1 和 3D-G0 通过之后，不增加四麦三维验证前置条件。旧“3～5周”估算基于四路复用，不能直接用于六路扩展，工期等待 3D-G0 后纳入采集与合同联调重新评估。

用户已授权主流程提前开展六麦声学评审与离线软件模拟，属于 3D-G0 预研，可为六麦几何、声学表现和预算评审提供证据，不必等待 V1 完成才运行模拟。本文“单文件指南”限制仅适用于本任务，不限制主流程上述授权；本任务不重复跑模拟或修改主流程代码。模拟结果仍须标明假设与证据等级，不能替代 V1 保底门、3D-GA 真实采集或三维板测。

六麦 A/B/C 使用同一组六路输入：A 为其中固定单麦参考，B 为六麦手动真实指向，C 为六麦自动估计指向。该对照不要求四麦方案、四麦模拟或四路子阵列；各输出保持相同场景、频带与增益规则。

## 2. 独立核对与计划缺口

### 2.1 已核对成立的部分

在阵列中心为原点、`x` 朝前、`y` 朝左、`z` 朝上的右手系中，方向向量定义为

```text
u = [cos(e) cos(a), cos(e) sin(a), sin(e)]
```

其中 `u` 指向声源。若 `tau_ij = t_i - t_j`，远场近似为

```text
c * tau_ij = -(r_i - r_j) dot u
```

负号与该时差、方向定义一致，但必须用已知 `+x/+y/+z` 方向的合成用例和非共面实录再次校验，不能根据界面显示方向“看起来正确”判断符号。

平面四麦的基线矩阵第三列为零，无法直接观测 `u_z`；单位模约束最多在附加半空间先验下恢复俯仰绝对值，仍不能消除上下镜像。四麦非共面且参考基线矩阵秩为 3 才具备三维线性可观测基础；六对 TDOA 只有三个独立到达时间差自由度，其余对用于冗余一致性检查。这些是理论结论，不是精度或实板通过证据。

对 N 个通道，全部无序 pair 数为 `N(N-1)/2`，相对到达时间至多有 `N-1` 个独立自由度：四麦为 6 对/3 个自由度，六麦为 15 对/5 个自由度。远场几何矩阵只有三列，其秩至多为 3；六麦满秩及 15 对都不保证精度。若选择部分 pair 或屏蔽通道，须针对实际保留集合重新检查秩、条件数、残差和系数版本，不能只检查“剩余麦克风不少于四只”。

### 2.2 当前计划仍缺的接口决定

现有合同有 `hardware_id`、`interface_version`、`build_id`、`config_version`、`sample_id/frame_id`，工程文档也已使用 `geometry_version`，但以下关系尚未冻结：

1. `geometry_version` 是寄存器可读值、结果帧字段，还是仅存在于实验 manifest；
2. 标定使用独立版本号/内容哈希，还是被 `config_version` 完整覆盖；具体新字段名未定；
3. 每个方向结果如何证明与同一帧的 `config_version`、几何和标定属于同一个原子快照；
4. V1/V2 如何声明支持二维或三维，如何表达“方位有效但俯仰不支持”以及“向量有效但极点方位无定义”；
5. V2 增加字段和六路数据后，V1 方位字段、已有地址/偏移与旧四路 DMA 视图怎样兼容；
6. 通道数、传输通道顺序、有效通道集合、pair 顺序/符号、几何和标定怎样原子绑定；屏蔽通道后是保留固定槽位还是改变打包长度。

因此，当前不能让通用 Skill 猜测版本字段，也不能先写 PYNQ 解析代码。接口负责人应先冻结项目专用 schema 和兼容策略；在此之前，三维板测入口保持关闭。

## 3. 版本职责与禁止混用

以下命名沿用现有合同，职责必须分开：

| 标识 | 应回答的问题 | 不应被用来代替 |
|---|---|---|
| `hardware_id` | 当前 PL 硬件家族/设计身份是否正确 | 精确构建或数据格式版本 |
| `interface_version` | AXI4-Lite、DMA payload 和事件语义是否兼容 | 每次 Overlay 重编译、几何或标定编号 |
| `build_id` | `.bit/.hwh/manifest` 是否来自指定构建 | 运行中实际生效的配置 |
| `config_version` | 某次影子配置提交后哪组参数已原子生效 | 长期稳定的几何/标定内容身份，除非合同明确包含并可追溯 |
| `geometry_version` | 阵元坐标、通道映射、坐标轴和求解系数是否同源 | 标定或接口版本 |
| 标定版本或哈希 | 固定延迟、增益和相关校准数据是否同源 | `geometry_version` |
| 数据格式版本 | 录音块、结果帧或 golden 文件怎样解析 | `interface_version`，除非二者被明确规定为同一版本域 |

`geometry_version` 已出现在工程和录音元数据要求中；标定版本/哈希的最终命名尚未确定，本文不替接口负责人做实现决定。最低不变量是：每个可判定的方向结果必须能追溯到唯一的接口、构建、配置、几何、标定和数据格式组合。只记录 Notebook 参数或文件名不满足这一条件。

## 4. 通用 Skill 与 SoundSight 扩展的分层

### 4.1 通用 Skill 保持不变

通用层继续只理解：

- profile、板卡、完整 part、PYNQ 镜像和兼容标识；
- `.bit/.hwh/manifest`、哈希、`build_id`、`interface_version`；
- AXI4-Lite IP、寄存器表和身份读回；
- AXI DMA 通道、长度、beat、buffer 对齐、flush/invalidate、TLAST、超时和错误状态；
- 外部提供的输入、实际输出、golden 文件、比较格式/容差；
- 吞吐、延迟、时序、资源以及 `static/mock/hardware` 证据等级。

不得在通用脚本中新增 SoundSight 专用“二维/三维模式”、固定四路/六路或 6/15 pair、角度单位、方向字段名、阵列坐标、寄存器地址或无效原因枚举。

### 4.2 SoundSight 提供项目专用扩展

后续由 SoundSight 的接口或测试 manifest 描述：

- 坐标原点、轴方向、右手系、角度正方向和角度单位；
- `u` 是指向声源还是波传播方向，`tau_ij` 的顺序和符号；
- V2 六路的通道数、物理编号、传输顺序、三维阵元坐标和标定项的逐项映射；V1 四路格式仅沿用既有合同用于兼容检查；
- 有效通道集合、实际使用的 pair 列表、顺序、时差符号和对应求解系数；
- `geometry_version`、标定身份和 `config_version` 的绑定方式；
- V1 二维输出、V2 三维输出及各字段有效性；
- payload 长度、字节序、定点格式、帧边界和 `frame_id`；
- 每个用例的输入、期望输出、容差和预期错误状态。

项目专用 schema 的关联约束由后续经评审的项目测试负责，通用 Skill 复用现有文件哈希、身份检查与数据比较入口。把新元数据放入 profile 不代表现有脚本已经校验了通道、pair、几何或标定关系；`compare_golden.py` 的字节或数值比较也不能替代版本和有效性检查。Python 可以生成离线参考和展示结果，但 PL 实时方向计算不能依赖 Python。

### 4.3 六路数据合同与旧四路兼容审查项

下表只列审查语义。`channel_count` 是本轮通道数审查标签，channel order、pair、geometry、calibration 均不据此确定新 JSON 键、寄存器名、地址或布局；已存在的字段继续沿用正式合同命名。

| 审查项 | 待冻结的不变量 | 必测错误 |
|---|---|---|
| 通道数与顺序 | 声明的传输槽位数与通道顺序一致；物理编号唯一，每项有坐标与标定关联；4/6 与 2D/3D 独立 | 声明六路却仅四项顺序、重复通道、上下麦交换、用维度推断数量 |
| 有效通道集合 | 区分装配、传输和参与求解的通道；屏蔽后的槽位策略明示 | 屏蔽一麦后解析器擅自把六路步长变成五路；未记录的自动压紧 |
| pair | 实际列表端点有效、顺序和符号固定；无重复/自配对；与 TDOA、质量、合法 lag 和系数逐项对应 | 未声明子集却沿用旧四路 6 对表、pair 换序未换系数、引用已屏蔽通道 |
| 几何与标定 | 坐标单位、通道身份、几何版本、标定身份及适用配置一致 | 六项几何配四项校准，旧夹具录音套新几何，同编号不同内容 |
| 长度与打包 | 格式版本决定头部、槽位、样本组数、存储位宽、字节序、padding 和 TLAST；DMA 长度与合同互证 | 截断/多字节、头部长度与实际不符、把六路按四路重分组 |
| 配置生效 | 同一结果帧及其输入使用一个可追溯配置；`config_commit/config_version` 与几何、标定、通道/pair 集合在安全边界一致生效 | 提交未确认即按新布局读旧帧、跨帧撕裂、版本相同但布局或系数不同 |

以纯定长 PCM 为例，载荷预算为 `样本组数 × 传输通道数 × 每通道存储字节数`，头部、padding 和协议开销另计。同样本组数/位宽下，六路载荷为四路的 1.5 倍；这只是预算，不是 DMA 实测速率。六路两组共 12 个通道样本也可能被四路解析器误读成三组，因而“总长度能被四整除”不能作为兼容判据。必须先判定支持的版本和布局，再核对精确长度与组数；拒绝截断取前四路、补零或猜测格式。

本轮取消六路导出四路子阵列实验。旧四路兼容使用已有 V1 协议、样例或拒绝测试核查，不要求从六路数据生成四麦声学方案。若未来重新考虑四麦备选，由主流程另行决定范围。

## 5. 方向有效性的验收原则

单独满足 `||u|| = 1` 不能证明三维方向有效。错误 TDOA 经过归一化也能得到单位向量，因此项目 golden 和板上证据至少要同时检查：

- 原始解归一化前的模长或等价可行性指标；
- 使用同一 `geometry_version` 重新计算的几何残差；
- 实际有效通道和 pair 集合、集合对应的几何秩/条件数、TDOA 闭合/一致性和每对质量；
- 总方向有效标志及明确的无效原因；
- `frame_id`、时间戳和配置/几何/标定快照的一致性；
- 单位向量分量范围与模长容差；
- 由向量复算的方位/俯仰与输出角度是否一致。

有效性至少需要能区分以下状态，具体编码后续冻结：

| 情形 | 正确语义 |
|---|---|
| V1 只提供二维方位 | 方位可有效；俯仰和 `u_z` 为不支持/未知，不能填 0 冒充测量 |
| V2 普通方向 | 向量、方位、俯仰按各自规则有效 |
| 正上或正下 | 向量和俯仰可有效；方位无唯一意义，应单独无效 |
| 低能量、对数不足或残差超限 | 整体方向无效，不能仅归一化后输出 |
| 几何/标定版本不一致 | 本帧无效或明确报合同错误，不能混用后继续计算 |
| 旧客户端不认识 V2 payload | 拒绝解析或进入已声明兼容的 V1 视图，不能按旧长度盲读 |

| 客户端/测试程序 | Overlay 或数据 | 期望行为 |
|---|---|---|
| V1 | V1 | 现有二维 golden、寄存器身份和 DMA payload 全部回归通过 |
| V2 | V1 | 可显式进入 V1 兼容模式；三维请求必须返回“不支持”，不得把俯仰当 0 |
| V1 | V2 | 只有在 V2 明确保留 V1 地址、方位语义和旧 payload 视图时才允许运行；否则接口版本不匹配并停止 |
| V2 | V2 | 核对能力、长度、单位、有效标志和全部版本绑定后才解析三维结果 |
| 任意 | 错误 `.bit/.hwh` 或错误 `interface_version` | 在写配置和启动 DMA 前 fail closed |
| 任意 | 正确接口但错误 `geometry_version`/标定身份 | Overlay 可加载不等于结果可用；方向用例必须失败 |
| 旧四路解析器 | 六路 payload，包括总长恰可按四路整除的情况 | 按不支持的版本/布局安全拒绝，不能生成伪四路样本或方向；若旧客户端无此门禁，上层必须阻止其接入 |
| 后续客户端 | V2 六路 payload 或既有 V1 四路样例 | 独立检查版本、通道数与方向能力，选择支持的 schema 或拒绝；不新增四麦三维数据生成任务 |
| 任意 | 六路传输、单通道屏蔽 | 依据冻结槽位策略解码；结果保留实际有效集合，不冒充全六路正常运行 |

旧二维兼容不是“V2 在水平声源下能输出相近角度”这么单一。还必须证明旧寄存器复位/访问语义、旧 DMA 长度与 TLAST、旧 golden、错误码和超时路径未改变。若 payload 必须改变，应通过新的数据格式/接口版本显式拒绝旧解析器，而不是依赖数组越界后发现问题。

## 7. Mock 与硬件分层案例

### 7.1 Mock/静态层

以下是六麦项目接口验证及旧协议兼容的拟议用例，不是板上通过，也不是要求主流程本轮一次性完成全部用例。已有 21 个声学模型自检与部分用例主题相关，但未形成下表逐项接口证据映射，不能据此把全表标为已通过。新增声学向量仅针对六麦；V1 用例复用届时已具备的样例，缺失项登记待提供，协议拒绝不需要新增四麦声学模拟：

| 用例 | 输入或故障注入 | 必须检查 |
|---|---|---|
| `3d-mock-axis` | `+x/+y/+z` 和对应理想 TDOA | 时差符号、轴方向、角度单位、向量与角度互算 |
| `3d-mock-octants` | 八个象限及上下半球方向 | 方位环绕、俯仰符号和球面夹角 |
| `3d-mock-poles` | 正上/正下 | 向量有效、俯仰有效、方位无效 |
| `3d-mock-planar` | 将六麦坐标错误配置为共面，作为六路合同故障输入 | 检测秩不足；不得宣称完整三维，不另建四麦模拟 |
| `3d-mock-version-mix` | TDOA、系数和标定来自不同版本 | 明确拒绝，不产生有效方向 |
| `3d-mock-invalid-residual` | 可归一化但几何残差过大的 TDOA | 有效性失败，证明不能只检查单位模 |
| `compat-v1-golden` | 冻结的旧二维寄存器/DMA/golden | V1 输出位精确或按既有容差一致 |
| `compat-unsupported-3d` | V2 客户端请求 V1 固件输出三维 | 返回不支持，不产生 `elevation=0` |
| `compat-wrong-interface` | manifest/HWH/身份寄存器版本冲突 | 静态冲突在下载前拒绝；实际身份读回冲突在配置写入/启动 DMA 前停止 |
| `compat-length-change` | 旧解析器读取新长度，或反向组合 | 按版本拒绝；不得截断、补零或错位解析 |
| `compat-six-to-four` | 六路两组载荷交给旧四路解析器 | 即使字节数可整除也拒绝，不能误报三组四路数据 |
| `contract-channel-map` | 六路注入逐通道可区分码，交换或重复顺序项；V1 仅复用已有样例 | 通道数、顺序、槽位和物理映射一致；不能靠全通道相同输入掩盖错序 |
| `contract-pair-map` | 六麦全部 15 对或明确的子集；换序、重复、反向或无效端点 | TDOA 与质量/系数按相同 pair 顺序对应；不要求所有用例必须算满 15 对 |
| `contract-calibration-size` | 六项坐标配四项标定、同版本不同内容或旧夹具数据 | 关联失败并拒绝，不能把缺失校准补默认值后报告通过 |
| `contract-bad-length` | 短一字节、多一字节、头部/样本组数不符、错误 TLAST | 在解码/消费前拒绝；保留请求/实际长度与失败位置 |
| `contract-config-boundary` | 新通道/pair 配置提交时仍返回旧帧，或几何/标定部分更新 | 根据实际生效版本路由或拒绝；不能只用当前 Notebook 配置解释在途帧 |
| `contract-count-dimension` | 六路声明缺失或不支持三维能力，并读取既有 V1 能力样例 | 通道数不是维度枚举；不得仅因六路就认定三维有效，无需四麦三维向量 |
| `contract-channel-mask` | 六路屏蔽一麦或错误自动剔除的故障用例 | 固定槽位/压紧规则一致，重检所选几何；已知屏蔽与自动故障识别分开报告，不构成四麦方案比较 |

每个 golden 用例保存输入哈希、通道数与顺序、有效集合、pair 表、坐标和版本身份、预期有效性、期望字段、容差、首个差异和随机种子。本任务未生成或执行这些接口 mock，也未新增脚本；主流程已有六麦软件结果按第 1.1 节单独登记，不再描述为“尚无六麦结果”。定点整数/打包路径优先位精确；角度/向量容差必须在正式测试前由量化预算给出，不能根据结果临时调宽。

### 7.2 硬件层

下列是未来硬件阶段的验收建议，实际执行须取得对应实施授权，且具备已核实的 PYNQ 板、Overlay 与 DMA 路径。V1 与 3D-G0 通过之前不进入扩展采集实施；主流程已授权的 3D-G0 离线声学评审与软件模拟可以先行。六路专用测试不能用于宣称 V1 已通过。

| 阶段 | PYNQ/测试侧工作 | 证据边界 |
|---|---|---|
| 3D-GA 准入审查 | 审核六路实际接口、共享时基、版本化合同和安全路径；核对板卡、镜像、同构建 `.bit/.hwh/manifest` 与接口身份 | 材料一致只允许进入授权的采集验证，不代表六路已采集 |
| 3D-GA 采集验收 | 身份读回、DMA loopback、缓存/TLAST/超时；逐通道可区分码、同步与重启、固定差异；六路长录音一小时无丢样/乱序，按 `sample_id`、块长与错误计数交叉核对 | loopback 不能替代真实六路同步采集 |
| 3D-GA 格式与配置边界 | 验证六路旧四路解析拒绝、坏长度、在途旧帧、配置生效确认；记录实际传输/有效通道及 pair、几何、标定绑定 | 负例应受控，拒绝是负例通过条件；不能通过向实时链随意写非法 DMA 地址制造故障 |
| 3D-G1 实录 | 以通过 GA 的六路录音完成离线标定和方向评价，保留遮挡、噪声、已知异常屏蔽与自动识别的独立结果 | 支持声明场景内的真实录音算法结论，尚不证明 PL 三维实时输出 |
| 3D-G2 PL 回归 | 通过审核的项目测试入口回放轴向/极点/版本混用/无效残差 golden；检查同帧版本、结果有效性，并回归冻结的 V1 接口及二维向量 | 通用 `pynq_probe.py` 只做其已支持的身份/loopback；不能把它当成已实现的三维算法驱动 |
| 3D-G2/G3 性能与系统 | 记录六路实际 DMA 长度、地址对齐、缓存操作、错误状态、首差异、吞吐和延迟；另交 Vivado 2025.2 时序/资源及同组六路输入的 A/B/C | 预算、综合报告、传输性能和三维声学实测分别报告；A 是固定单麦参考，B/C 均为六麦波束 |

保留 V1 可恢复发布物；六路不能冒充未声明的旧四路视图。若未来明确提供四路兼容视图，应单独回归该视图的固定长度、顺序、版本和方位语义。通用 Skill 的 `hardware` 等级与声学计划的 E0～E5 是两条不同维度：一次 DMA board loopback 不能自动升级为 E5 三维 DOA 实测。

## 8. 停止条件

出现以下任一情况时停止相应的三维 PYNQ 硬件或接口验收，不实现临时兼容补丁。硬件准入条件尚未满足，不阻止主流程执行已授权的 3D-G0 离线评审与模拟：

- 二维 V1 的 M0～M6 尚未通过，而三维硬件实施或联调影响 V1 交付；
- 完整器件、PYNQ 镜像、Overlay、DDR/DMA 或安全 loopback 路径仍未核实；
- V1 或 3D-G0 未通过即进入扩展采集实施，或未通过 3D-GA 就用同步状态未知的多通道录音评价三维算法；
- 坐标系、TDOA 符号、角度单位、方向含义或六路映射不唯一；
- 通道数、槽位、有效集合、pair、几何和标定不一致，或通道屏蔽后的长度策略未定义；
- 六路载荷被旧四路解析器接受，或配置切换时按新布局解释旧帧；
- `interface_version` 的兼容政策、payload 长度或能力声明未冻结；
- `geometry_version`、标定身份和 `config_version` 无法绑定到同一结果帧；
- V1 缺少俯仰时仍用数值 0 表示，或极点方位未提供独立无效语义；
- `.bit/.hwh/manifest`、身份寄存器或项目 schema 版本冲突；
- mock/静态结果被写成板上通过，DMA loopback 被写成三维声学通过；
- 三维计算被移入 Python 实时循环以规避 PL 验收。

PYNQ 准入失败时，按现有路线切换 Vitis/PetaLinux 控制层；接口、向量、版本兼容和证据判据保持不变。

## 9. 后续交付与主流程决策

本任务在 V1 验收前只准备以下轻量指南内容：版本兼容矩阵、项目专用 schema 审查项、合成 golden 清单、旧二维回归向量索引要求和上板执行顺序。它们不得写入通用 Skill 的固定逻辑；主流程另行开展的已授权离线模拟不受本任务单文件范围限制。

主流程在 V2 接口冻结前必须决定：

1. 标定身份采用独立版本号还是内容哈希，以及它与 `config_version` 的关系；
2. `geometry_version` 和标定身份放在每帧结果、状态快照还是可证明不可变的会话 manifest 中；
3. V1/V2 使用兼容追加、双 payload 视图还是明确断代，并给出 `interface_version` 兼容表；
4. 能力发现和分字段有效性的项目语义，尤其是 V1 俯仰未知及极点方位无效；
5. 冻结哪一批 V1 二维寄存器/DMA/golden 作为不可回退基线；
6. 在当前 3D-G0 六麦评审中确定候选几何、实际 pair 集合和预算；在 GA 前冻结传输/有效通道语义、屏蔽后的槽位规则，以及通道/几何/标定同帧绑定方式。六麦不满足条件时回报原因，由主流程重新决策，不自动追加四麦模拟或对比；
7. 纳入 3D-GA 的实际采集、版本合同与联调工作重新估算 V2 日期。

已有 47%/26% 有效率等失败结果仍需人工复核评价口径、目标选择规则及下一轮六麦改进优先级；不能以材料整理完成代替这些决定。材料包发布路径与完整性由主流程复核，本任务不自行发布、重跑或归档。

在这些决定完成且 V1 主线通过前，本指南不授权修改 `pynq-overlay-dma-validation`、PYNQ 驱动、AXI 寄存器、DMA payload、RTL 或 Vivado 工程。
