## 四类聊天职责

| 类型 | 负责 | 不负责 |
| --- | --- | --- |
| 工作执行 | 确定当前阶段任务、范围与下一步；下发给工程实现；接收成果，推送任务分支，生成给复核人的复制提示词 | 不与工程实现抢写源码，不自行技术批准 |
| 工程实现 | 带领成员按单实现、调试、测试，回报路径、命令、结果与未完成项 | 不扩大任务、不自行合入main |
| 承接别人外包 | 完成其他成员明确委托的工作；记录委托人、输入、输出和验收人，交回委托流程 | 不承担本人本阶段主任务 |
| 复核别人任务 | 固定对方远端SHA和范围，独立核查；通过后负责合入、推送、清理及回报 | 不边改作者方案边自审，不扩大批准范围 |

工作执行 → 工程实现 → 工作执行（完整交付、推送）→ 成员复制提示词给复核人 → 复核通过 → 合入main、验证、清理、回报。

A复用现有任务，不再新建同名聊天：

- 工作执行：SoundSight｜拓芙工作执行。
- 工程实现：SoundSight｜工程实现。
- 承接外包：SoundSight｜A 承接 B 外包：H2 实录采集。
- 复核：SoundSight｜A 成员任务复核。

B/C在各自设备建立或复用这四类聊天；A电脑不能替代B/C实际配置。其他专项聊天按需要由成员自己创建。主流程管跨成员、阶段与集成清理，不是第二个工程实现。“SoundSight｜C 外包任务与验收”是派给C的专项管理/复核入口，不是C本人承接实现的聊天。

## 一次完整交付

1. 一个任务只有一个正在修改的源码位置和负责人；先读上次回报与真实文件，不按旧操作单重复开工。
2. 聊天不同不等于文件隔离。并行前约定各自写入范围，必要时使用临时工作树；禁止两个任务同时修改同一one或构建。
3. 成果集中到已有任务包，包内持续迭代，不为函数、截图或每次实验新建包。公共源码和输入引用准确版本，不整仓复制到payload。
4. 工程实现回报后，工作执行检查交付完整，推送个人任务分支、核对远端SHA，再生成提示词由成员复制给复核人。“已推送”不是“已批准”。
5. C本轮只保留用户线下已安排的三维转台方案，不从本流程追加工作或交期。既有004-R2暂缓、005不启动；原操作单约束只作为以后另获授权时的执行方式，不自动派工。

提示词须包含：仓库/分支/准确远端SHA、包路径、批准申请范围、相对上次改动、测试和未测试项、复现命令、依赖、目标活动路径、可清理的短期分支/副本。未推送不填假SHA。

## 六项增量复核规则

目标是减少重复读取、重复推理和无关复跑，不是减少必要测试。A/B 仍交叉独立复核；作者不能自批。H1/H2/H3、正式阶段验收和证据真实性不变，不新增交接点或 C 的任务。

### 1. 首次完整审，返修只审增量

- 首次交付完整检查**本次申请范围**的合同、关键实现、测试判据与实际证据，不等于审整个仓库。
- 返修固定上次受检 SHA、新候选 SHA、问题编号及旧结论，检查差异、原失败输入、相邻边界和受影响的依赖/调用链；复核人独立执行必要检查，不直接接受作者 PASS。
- 已通过且源码、相关依赖、输入、合同及工具配置均未改变的部分引用准确旧报告/版本，标为“复用，未重跑”。旧版 NEEDS_FIX 不是整包批准，只能复用其中明确通过的子项。
- 纯说明/路径索引修改做语义、链接和范围检查；测试脚本、判据、配置、接口说明或命令变更不按“只是文档”减免行为检查。
- 合同/数值格式/采样映射、公共算法、时钟复位/CDC、DMA 内存所有权/安全停止、构建加载身份等变化，或依赖/环境变化、证据不匹配、影响范围不明时，扩大受影响验证。必要时执行该包全回归；写清触发原因，不默认全仓重审。

### 2. 脚本执行，摘要优先，异常再展开

- 优先复用已有包级 `reproduce`、测试、清单/哈希检查入口；仅缺失且确有需要时补脚本，不每轮重写同一核查器。固定准确代码、输入及输出目录后，批量运行已选命令。
- 命令、工具版本、退出码、完整 stdout/stderr、结果和必要哈希留在本轮**全新路径**。向模型先提供测试/检查数量、失败与预期负例、首错及日志路径；按差异阅读关键实现与测试判据，失败或矛盾再打开相应完整日志。
- 不将整仓文件列表、大清单、重复成功日志和历史报告全文反复灌入上下文；机器可比的内容由脚本汇总差异。原始失败和证据不删改，不通过忽略、截断保存或改清单隐藏问题。
- 脚本退出 0 不是自动批准；负例须核实失败发生在预期阶段/原因，工具启动失败不算故障检出，重复测试不叠加成独立用例。摘要须说明本次运行、复用与未测，不只显示 PASS。

### 3. 合并后做相称验证，不默认第二轮完整审

- 无冲突且批准范围、相关依赖、配置、工具环境及入口保持一致：核对合入内容与批准版本的 Git 对象/必要字节身份，再从最终路径执行最小可运行检查（smoke test）；只改说明时可用链接/范围检查。无需重新进行整轮独立推导和全套仿真。
- 路径搬迁须确认实际加载的是新位置源码，检查导入、文件清单及运行入口；路径相关测试仍要跑，不能仅以哈希相同代替。
- 冲突解决、代码/依赖/配置/判据变化或集成测试失败时重新检查受影响部分，必要时全回归；不能把合并解决产生的新代码视为原批准自动覆盖。
- 正式 H3、阶段检查及 10/1 总验收仍执行原约定的系统级判据。无变化的子项可引用可信旧证据，但集成、时序、实板等新要求不能由包级 PASS 代签。

### 4. 每份完整交付只设一页复核入口

- 复用现有 README/REVIEW，按[一页模板](templates/review-brief.md)填写；已有同等信息的入口直接使用，不要求为了格式另建包或复制历史。
- 一页包含准确版本与范围、相对上次变化、申请批准/不申请批准的内容、依赖、检查命令及结果摘要、已知问题、活动路径和收尾位置。证据通过链接引用，不重复粘贴。
- 工作执行先核对关键材料可用；缺失准确版本、必要输入或可执行入口时一次列出缺项，退回补齐，不让复核任务反复猜测或全仓寻找。能独立审的完整子包可先审，不等不相关子包。

### 5. 完整交付再审，小实验不逐次审批

- 工程实现可按合同独立进行离线实验；达到已约定完整交付条件后由工作执行一次发布并交审，同包持续迭代，不按函数、截图、单次实验拆审批。
- 首轮在约定范围内集中查合同与高风险点，同类问题尽量一起回报。发现阻断后完成相关问题定位，暂停不会改变当前结论的昂贵无关复跑；已经发现的问题及尚未检查部分如实列出，不宣称问题清单穷尽。
- 区分“阻断本次申请”“非阻断观察”“范围外未测”。返修只关闭相应问题及必要回归，非阻断项按已有台账/风险入口记录，不随每轮返修新增门槛；真实针脚冲突、错电源、短路等安全问题仍必须处理。
- 不因限定归档批准要求补齐整机证据，也不因节约额度把诊断批准升级为正式 M1/H3、声学性能或实板通过。

### 6. 技术复核与发布收尾分开

- 复核任务负责合同正确性、关键风险、独立反例和准确范围批准；工作执行负责交付完整性/版本及协调，复核人或获授权主流程负责已批准内容的发布收尾。不得再由多个任务重复签同一轮技术批准。
- Git 范围/版本核对、包清单/哈希、例行测试、摘要和本批遗漏检查优先复用固定脚本/命令；模型处理异常、范围判定和技术结论。清单/日志解析器也有适用边界，不能把未验证解析器当事实来源。
- [每批发布核对](#batch-closeout)仍逐批执行；按本批清单查相关本地材料，不扫描整台电脑或重跑无关阶段。没有新变化就引用本批已完成检查，不为每个小动作另建报告/包。
- 合并、推送、删除和真实硬件操作仍按原权限执行，脚本不得自动授权这些动作。主线已发布、成员已同步、通知已送达、对方已接收是不同状态，不能互相代替。

### 落实与回报

各成员工作执行在下一次现有任务回报中注明采用“2026-09-17 增量复核”；工程实现沿用既有复现脚本及单一源码；复核任务在现有报告补充“本次运行 / 复用依据 / 未测 / 扩大范围原因”；主流程查发布与本地对齐。使用[当前通知入口](phases/2026-09-13-to-10-01/dispatch.md)传递，不要求另开聊天、建立回执任务包或等待全员回执才能开工。C 不因此新增研发或交期。

## 每次复核通过后的收尾

由复核人或获明确授权的主流程执行，不再等待下次阶段日期：

1. 核对分支仍为批准SHA，新增未审内容不得夹带。
2. 获准且适合接入的源码进入活动目录并更新统一入口；只获研究/诊断批准的材料保留相应身份，不默认替换算法或实际工程。暂不能接入者说明原因和下一步。
3. 按[第3项](#review-efficiency)在新位置/合并后做相称验证，不默认第二轮完整复审；非强制推送main，然后执行下节的本地与远端核对、未提交材料处理；不能以推送成功代替批次收尾。
4. 确认整条短期分支已完成、内容已入库或明确保存、没有继续任务后，删除本地/远端短期分支。成员长期分支保留；部分批准的分支不整条合并/删除。
5. 清理已结束的复核/发布工作树、重复解压副本和无用构建输出。先检查准确路径、独有/未提交/忽略文件和可恢复性；必要材料集中为一份校验备份，不保留多个活动工程。唯一原始数据不能当垃圾删除。
6. 报告批准SHA、main提交、验证结果、活动入口、本地/远端核对和本批遗留材料处置、已删除对象、恢复位置和保留项。推送失败或保护/权限阻断时明确未完成，不先删源分支。

作者不自审自合。限定研究/诊断通过可以按范围归档集成，不能冒充完整系统通过。A/B交叉技术复核，C不承担复杂技术审批。

## 每批发布后的本地与远端核对

2026-09-12 起按拓芙补充要求执行。每一批任务在“复核通过并推送 main”后立即检查，不等待阶段日期，也不要求每个小实验单独交包。责任人是本批复核合入者或获授权的主流程；工作执行提供相关文件位置，工程实现说明原件/缓存用途。

1. **固定本批范围。** 记录批准 SHA、批准文件/目录、活动入口、任务包以及本批使用的工作树、录音/结果/日志位置。以此识别本批遗漏，不无差别扫描或改动整台电脑。
2. **核对真实 main。** 刷新远端状态，分别记录实际共享项目的本地 main、`origin/main` 和直接查询的远端 main SHA，核实领先/落后数量及本批路径内容。不能只查隔离发布工作树或把 `origin/main` 当作永远最新。若远端已有合法新提交，安全同步最新主线并确认本批批准提交仍被包含；不要求回退到旧发布 SHA。
3. **查清本批本地材料。** 同时检查已修改、已暂存、未跟踪和被忽略的文件；对照交付清单确认源码、测试、原始输入、录音、结果、报告及复现依赖是否已保存。特别检查 `*.wav`、`*.bin`、日志等是否被宽泛忽略规则漏掉。无关在做任务单独列明并保留，不把它们算成本批未完成，也不为获得全仓零差异而误删或夹带提交。
4. **有用材料当批处理。** 已在准确批准范围内但漏提交的材料补入 main；新增或未复核实现先提交并推送原有或必要的独立待审任务分支，给出准确 SHA 和复核入口，不能直接混入 main。不适合公开的大文件、第三方内容或隐私材料保留到明确的受控位置，记录来源、哈希、用途和恢复方法，公开边界不明时先取得授权。可正常版本管理的成果不能仅留 stash、备份 ZIP 或未提交区，把“已经备份”当成完成。
5. **核对后去重。** 相同材料确认内容与引用后指向唯一有效位置；旧工程/缓存须验证可恢复性及实际工程是否依赖它，再按既有授权清理。冻结证据保留原字节，必要时设置合适的换行规则；不得改哈希清单、加忽略规则或删证据来掩盖缺件。存在清单时检查已提交内容，路径/打包有变化时从最终提交取出相关材料做相称验证。
6. **再检查并回报。** 若有补提交，再次核对本地 main、跟踪引用及实际远端。回报本批相关的未处理差异数（应为 0）、有用材料去向/提交号、仍保留的其他任务、删除与恢复位置。不要求其他在做任务的工作区全局为零；但必须如实报告它们，且不得谎称整个目录干净。

完成条件：本地/远端主线同步已核实，本批有用材料无未说明的遗漏，处理与验证结果可追溯。遇到脏共享目录、分叉、权限/保护或材料公开范围不明而无法安全完成时，标为“已发布，批次收尾待处理”，写明差异、负责人及下一步；保留工作，不强推、不切换/重置脏目录。相关短期分支在材料去向确认前不删除。

将以下简表追加到已有批次复核/发布记录即可，不为每次检查另建一套任务包：

| 回报项 | 必填内容 |
| --- | --- |
| 批次与批准范围 | 任务包、批准 SHA、批准文件/目录 |
| main 对齐 | 核查时间、本地/跟踪/实际远端 SHA、领先/落后数、本批路径一致性 |
| 本地材料 | 已修改/暂存、未跟踪、忽略项检查；本批未处理数量；无关改动说明 |
| 处理结果 | 补交 main 或待审分支 SHA、唯一材料入口、受控归档与哈希 |
| 验证与清理 | 实际检查、删除对象、恢复位置、保留项；没有就写“无” |
| 最终状态 | 收尾完成，或已发布但收尾待处理及责任人/下一步 |

B/C 在各自设备执行同样核对并回传结果。主流程通知本机聊天不等于已经检查 B/C 电脑；无法访问的设备不能代签“已同步”。本规则不新增 H1/H2/H3 交接点，不恢复暂缓的精细补证，不给 C 开放研究任务。

每阶段再按[阶段收尾](phase-closeout.md)集中汇总，不新增交接点；旧快照只读，补做记录带真实日期。坚持“一份活动源、一份必要原始证据、Git历史”，备份和整仓bundle放仓库外，不再提交重复整仓ZIP。
