# Git 分支与发布补充

2026-09-12更新。三人的聊天职责、完整交付、独立复核、每次通过后的合入和清理，以[统一工作流](team-workflow.md)为唯一正文。本页只规定Git命名与发布边界，替代旧“阶段后才进main、默认保留短期分支”的安排；旧版可在Git历史追溯。

## 分支使用

- main是团队已批准基线；复核通过的准确范围及时合入，不再等阶段日期。
- 拓芙长期分支codex/toph-development保留，B/C已有长期分支保留。长期分支不是所有任务进入main前必须经过的额外关卡，也不能整条带入未审工作。
- 一份完整任务需要隔离时建立一个短期分支，默认codex/<成员>/<任务>；拓芙可用codex/toph/<任务>。同包内部修改不反复建分支。
- 从已核实、适合任务的最新基线开始；有依赖注明准确SHA。不从过期个人分支携带无关历史，也不重置已有长期分支。
- 不能使用codex/toph-development/<任务>，它与已有同名Git引用冲突。

## 发布和清理

工作执行可按既有授权提交、非强制推送并建立待复核PR；只有另一成员的准确版本批准，或主流程明确的范围授权，才能合入main。作者不能自签。诊断/研究材料获批不等于默认替换活动RTL或正式硬件通过。

发布前核对仓库、源/目标、远端SHA、批准范围、文件归属和必要检查。当前remote为TophBeifong1744/Competition_fpga；每次重新确认。遵守远端保护和CI，不绕过评审、不强推、不改共享历史。

每批复核通过并推送后，执行[本地与远端核对](team-workflow.md#batch-closeout)：核对实际共享目录的本地main、origin/main、直接查询的远端main，检查本批已修改/暂存、未跟踪和被忽略的有用材料并处理到位。只核实发布HEAD或只做备份不算完成。若共享main有其他未提交工作，保留它们，使用一个可复用的干净发布工作区；不能切换/重置脏目录，也不能谎称共享目录已同步。新代码、原始证据、阶段快照的检查等级分别报告。

远端main成功更新后，确认短期任务整条完成且无新增未审提交，再删除对应本地/远端分支和已结束副本；保留长期、在做、部分批准及无法判断的分支。删除前记录SHA、独有文件和恢复方式。推送失败不先删源分支。

禁止全量暂存脏共享目录；禁止把供应商构建缓存、整仓ZIP和个人配置当作源码重复提交。未经授权不得改采购、烧录、上电、接口或完整H3状态。
