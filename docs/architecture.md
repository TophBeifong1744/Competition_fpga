## 1. 目标边界

本文为现行四麦二维 V1 架构，目标 2026-10-01，继续执行[四路样本合同](../hardware/four-channel-sample-interface-contract.md)。六麦 V2 软件预研不替换本架构，也不改变 V1 的采集数量、格式或阶段门。麦克风沿用用户已选 IM73D122V01/PDM，具体模块与板级接入仍待证据，不重新选型。最新状态见[当前状态](current-status.md)。

SoundSight 的最小闭环是：四路同步采集 → 已知方向声音输入 → PL 输出稳定 TDOA/DOA → 波束自动指向 → 增强音频输出。MVP 不包含语音识别、声纹识别、复杂多声源分离或由 PS/Linux 代替核心定位计算。PYNQ 已确定为首选开发、验证和演示控制层，但不属于实时声学数据面。

## 2. 数据面与控制面

### PL 数据面

```text
4ch mic interface
  -> channel align / sample valid
  -> DC blocker / decimation / FIR
  -> frame + window + overlap buffer
  -> FFT scheduler
  -> cross spectrum + PHAT weighting
  -> IFFT + legal-lag peak search
  -> sub-sample TDOA
  -> geometry solver + confidence
  -> steering-delay generator
  -> per-channel delay line / fractional delay
  -> sum / gain / saturate
  -> audio output and debug stream
```

设计要求：

- 四通道样本必须携带同一 `sample_valid` 语义，通道顺序固定且可追踪。
- 流接口优先使用 AXI4-Stream 语义；配置与状态使用 AXI4-Lite。
- 每次跨时钟域都必须显式使用异步 FIFO、握手同步器或等价结构，不能依赖仿真恰好通过。
- 每级记录数据宽度、二进制小数位、最大增益、舍入和饱和策略。
- 所有 FIFO 溢出/欠载、帧丢失和非法 TDOA 都应有黏滞状态位与计数器。
- 每通道每帧只计算一次 FFT 并保存频谱，六个无序通道对复用这些频谱；不得为每个通道对重复计算输入 FFT。
- 固定阵列几何后预计算 DOA 求解系数，PL 只做常系数运算，不实现通用矩阵求逆。

### PYNQ 优先的 PS 控制面

PYNQ/PS 负责：

- 写入采样模式、帧长、阈值、阵列坐标、声速、滤波器系数和手动/自动波束模式。
- 读取 DOA、置信度、帧号、错误计数、峰值质量和性能计数器。
- 驱动 LCD/UART/网络 UI，记录小规模调试数据并管理实验元数据。
- 在开发阶段触发带 `sample_id/frame_id` 的原始帧抓取，但不进入实时音频关键路径。短抓取可用 BRAM/FIFO，长录音通过 DDR 缓冲后由 SD 卡或网络导出。

PS/PL 边界固定为 AXI4-Lite 控制与状态、AXI DMA 批量数据和中断事件。Python 只能使用这些已版本化的接口，不能参与逐样本握手、决定 PL 内部流水时序或成为核心 RTL 的运行依赖。PYNQ 程序退出或 Linux 调度延迟时，PL 必须继续按冻结策略运行或进入可解释的安全状态。

PYNQ 是首选后端而不是不可替换依赖。M0 必须实测目标板的 PYNQ 镜像或板级支持、DDR、SD、网络、Overlay 加载和 Vivado 版本兼容性；若无法在项目期限内闭环，PS 实现切换为 Vitis 裸机或 PetaLinux，但寄存器、DMA 数据格式和验证向量保持不变。详细合同见 [PYNQ 集成与控制面指南](pynq-integration-guide.md)。

## 3. 时钟与复位

M0 必须画出真实板级时钟树后才能冻结本节。最低要求如下：

- 所有麦克风通道共享同一采样时基；禁止用四个自由运行的采样时钟拼成“同步”阵列。
- 采集时钟域与 PL 处理时钟域的转换有明确缓冲、满/空策略和复位顺序。
- 复位释放同步到各自时钟域；复位后帧号、延迟线、FFT 状态和统计计数的行为可预测。
- 音频输出与输入若使用不同采样时基，必须定义异步速率匹配方案。

## 4. 帧与延迟预算

初始算法基线为 48 kHz、1024 点帧、512 点 hop：一帧约 21.3 ms，方向更新间隔约 10.7 ms。系统目标“定位刷新不高于 50 ms”还包含缓存、FFT/IFFT、求解和 UI 传递时间。

40 mm 正方形只作为可调首版候选。在声速 343 m/s、48 kHz 下，边长和对角线的最大传播时差分别约为 5.60 和 7.92 个采样点，因此整数合法 lag 界分别为 6 和 8。5°变化在单条边基线正侧向附近只对应约 0.49 个采样点，最终精度目标必须依赖通道标定、亚采样估计和多通道一致性，不能只取整数峰值。

最终参数需用以下约束共同决定：

- 阵列最大物理时延与合法 lag 搜索范围；
- 低频定位所需频率分辨率；
- BRAM/DSP 资源与 FFT IP 吞吐；
- 方向刷新率和波束切换稳定性；
- 房间混响下的峰值可靠性。

## 5. 模块接口冻结顺序

1. `mic_rx`：硬件接口、通道顺序、采样格式、`sample_valid`。
2. `audio_preprocess`：输入/输出采样率、定点格式与群时延。
3. `frame_buffer`：帧长、hop、窗函数与 backpressure。
4. `gcc_phat_pair`：通道对调度、FFT 格式、归一化近似和 lag 输出。
5. `tdoa_doa`：坐标/声速格式、异常拒绝、角度和置信度格式。
6. `delay_sum`：最大延时、更新边界、插值结构、增益和饱和。
7. AXI 寄存器表：地址、复位值、读写权限和原子更新机制。
8. DMA/中断合同：数据块格式、缓存所有权、完成/超时/溢出语义和后端无关性。

接口变更必须先更新本文件或对应模块说明，再更新实现与测试。

## 6. 需要尽早验证的风险

- 麦克风模块是否能共享时钟并保持固定通道延迟。
- Zynq-7020 板卡 IO 电压、可用引脚和音频输出链路是否匹配。
- 麦克风间距是否在空间混叠、阵列尺寸和目标频段之间取得合理折中。
- PHAT 归一化的定点近似是否在低能量频点放大噪声。
- 单 FFT/IFFT 复用能否在 hop 周期内处理全部通道对。
- 混响、多径和双声源是否导致峰值跳变；置信度与平滑不能被省略。
- 实际板卡是否有可复现的 PYNQ 启动与 Overlay 支持，`.bit`/`.hwh`、Vivado 和 Python 环境是否匹配。
- Python、Notebook 或 DMA 异常是否会反压采集、破坏 PL 状态或留下无法恢复的缓冲区。

## 7. 目标方向与输出模式

纯声学时差只能估计声音来自哪里，不能识别“用户希望听谁”。首版必须明确采用手动方向扇区、锁定首次稳定方向或二者组合，并冻结保持与重新捕获条件。更响的竞争声源不应在没有规则的情况下自动抢占目标。

为分离阵列、定位和自动控制问题，系统必须支持三种使用同一四通道输入的可比输出：固定单麦、手动指定真实方向的波束输出、自动估计方向的波束输出。对应实验与指标见 [声学性能验证计划](acoustic-validation-plan.md)。

## 8. 六麦软件预研与后续硬件边界

[六麦软件评审](six-mic-acoustic-software-review.md)已有 2700 帧合成结果、21 个自检和独立复跑一致记录。低带内信噪比用例有效率 47%，等强竞争用例有效率 26%；这些结果说明已有可复现浮点基线及明确失败条件，完整 3D-G0 尚未通过。当前只做六麦评审，不新增四麦模拟或数量对比；资料入口为[独立材料包](../deliverables/six-mic-acoustic-review-v1/README.md)。

六麦未来扩展覆盖采集/抽取、缓存、通道与 pair 映射、6 次 FFT＋15 次 IFFT、三维求解、连续音频和 DMA；15 个 pair 不等于 15 个独立观测，也不代表资源或精度通过。完整预算与 3D-GA 尚未完成。V1 保底门和 3D-G0 通过后，仍需 3D-GA 的六路共享时基、复位、映射、固定差异、版本化格式拒绝和一小时长稳实测，这些是正式采集验收条件；此前安全条件满足后的短实录可作诊断，不必等长稳，三维 PL 验收仍须对应证据，见[三维工程指南](three-dimensional-doa-engineering-guide.md)。

软件模型可以在 PC 离线运行；这不改变 PL 实时核心与 PYNQ 控制面的边界。当前 C 音频使用有效帧的平均方向作整段静态指向，有效帧占比 43.55%，不能当作逐帧连续跟踪或在线自动波束的证据。

## 9. 后续扩展：自动声源跟踪转台

转台不是核心音频改善手段。对于全向麦克风阵列，电子波束可以在设备不转动时改变接收方向；只有存在摄像头、定向扬声器或其他确需朝向声源的载荷时，机械转动才有明确价值。默认考虑绕竖直轴旋转；实际被旋转的部件、负载、转角范围和线缆方案需在 M5 以后冻结。

控制链路为：

```text
PL: DOA + confidence + timestamp
  -> PS: 角度坐标变换 / 置信度门控 / 平滑 / 跟踪状态机
  -> PWM、方向脉冲或驱动器通信接口
  -> 电机与转台
  -> 编码器、限位或零位反馈
  -> PS: 位置闭环与故障处理
```

分工与约束：

- PL 继续负责实时声学算法，只输出角度、置信度、时间戳和状态；低速机械跟踪策略由 PS 负责。
- 若步进脉冲时序无法由 PS 稳定保证，可由 PL 提供底层脉冲发生器，但目标角度、速度规划和安全状态机仍属于控制面。
- 只有连续若干帧的置信度与角度稳定性达到阈值时才允许转动；低置信度、丢帧或定位异常时进入保持或安全停止。
- 必须设置死区、最大速度、最大加速度和方向切换约束，防止角度噪声引起机械抖动。
- 必须定义阵列坐标系、设备正前方、转台零位和电机位置之间的标定关系。
- 优先使用零位/限位保护；若需要连续旋转，必须单独解决线缆缠绕或采用滑环。
- 电机电源和驱动回流不得污染麦克风模拟/数字采集，电磁与振动噪声需通过静止/转动对照实验评估。
- 若麦克风阵列随转台转动，每个 DOA 结果必须与产生该结果的音频帧时间戳及当时转台位置配对，不能用当前姿态解释历史帧。

闭环联调以前，先用软件命令角度独立验证转台的方向、重复定位、限位和故障停止。转台采购与声源跟随联调至少依赖 M5 已证明的核心声学收益和明确载荷；若转台承载麦克风阵列，还需在转动过程中重新评估机械噪声与阵列坐标变化。
