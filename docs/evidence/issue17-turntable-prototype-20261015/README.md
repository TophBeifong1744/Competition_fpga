# Known-direction turntable increment

I17-B-TURNTABLE-PROTOTYPE-20261015. Product author candidate, pending non-author review. Parent C PR63 `b529fed84bde1d5d5d6326e0d8870416c738657a`. Existing seven C sources and their authority are unchanged. This adds an internal same-clock seam; no third Vivado project, pin assignment, acoustic result, PS driver or board validation.

## Concrete entry and parameters

`project/rtl/c_board/i17_turntable_prototype.sv` connects a finite, explicit known-result table to `i17_turntable_result_slice`. For actual direction results use **the slice**, not the known source. `i17_turntable_known_source` and `i17_turntable_pwm_guard` are the two supporting new modules. `sources.json` identifies the four new RTL and four unchanged leaf dependencies.

All ports use one clock, normally the existing native **61,440,000 Hz**. Reset is the existing active-low cold reset, asynchronously asserted with release synchronized by the caller. No derived clock/CDC/reset synchronizer is introduced. Never connect these multibit ports to arbitrary board pins or a different clock without a separately approved adapter.

Electrical parameters are mandatory: `CLK_FREQ_HZ`, `MAX_ANGLE_DEG`, `RESET_ANGLE_DEG`; invalid values fail simulation. C's H max360/reset180 and V max220/reset130 are electrical references, not actual mechanical approval. The prototype is one axis; V stays disconnected/disabled. Live inputs must explicitly supply valid configuration, S24Q8 offset, signed2 direction +1/-1, S18Q8 inclusive source domain, U9 mechanical min/max, and independent mechanical approval/output permission. Mechanical range must include the configured reset angle. Absent approval, output is closed and commands cannot be accepted. No production expiry, travel, speed, polarity, power or timing value is supplied by this increment.

Known-source configuration requires `CONFIGURED=1`, `COUNT=1..256`, `SPACING_CYCLES>=3`, packed `ANGLES_Q8` and packed **full725-bit** `IDENTITIES`; item0 is the least-significant slice. Prefer the smallest finite table (e.g. three entries), not a large mux. Clock/resource/timing results are NOT_RUN. Observe start low after cold reset, then explicitly raise it. A held-high start across reset/completion cannot auto-restart. Start accepted at edge S loads wait=spacing−1; entry0 is sampled at S+spacing. The first interval permits context/config recognition and the original gate's required strobe-low arming edge. Consecutive item sample edges are spacing cycles apart; each next tuple is exposed immediately after the preceding sampling edge, before its later strobe. STOP/output-revoke/fault/disable cancel the remaining source sequence without a new strobe on that edge. A new low→high start is required to replay; original runtime generation dedup still applies. A short interval is valid for digital diagnostics but may deliver only the latest motor target; physical demonstration must explicitly space entries beyond the output re-arm interval and C's approved motion/dwell conditions. No guarantee is made that every accepted table entry becomes a separate physical pulse/position.

`known_injection_o=1` identifies the source, not actual microphone truth. Prototype numeric/eligible/fresh inputs are deliberately constant true for the explicit known table and are **not evidence of real algorithm qualification**. Last table item identity/angle remain visible after done/cancel; done does not mean output has stopped or the actuator arrived. Commands may continue the electrical hold until explicit revoke. There is no invented timeout: a production lifetime owner must revoke expired authority explicitly.

## Result seam, identity and observations

The slice requires the complete active/result tuples to match: `{token64[724:661], generation64[660:597], context165[596:432], frame_first432[431:0]}`. Only result_strobe + matching identity + numeric-valid + delivery-eligible + fresh + no abort + valid mapping can issue a command, subject to the unchanged runtime gate's enable/config/session/arming/order checks. Existing `signed_angle_map` rejects source-domain or mechanical-range violations; no clamp/wrap is added. Its RNE and original motor pulse conversion are unchanged.

Runtime session=context165 and its window=generation64, matching the parent wiring. **Generation is not sample ID or a timing anchor.** Full frame identity is retained in `last_accepted_identity_o` on command acceptance; accepted_identity_valid remains sticky until cold reset. Same-angle new increasing generations are separate commands. A matching-session invalid/stopped increasing generation is consumed per the original gate and cannot later retry. Full mismatch does not grant a command even if the angle/context happen to match. The known wrapper's active tuple comes from its own table and only establishes the demonstration's declared provenance; real integration must use the actual independently retained lease/active tuple.

`command_valid_o` is combinational and is sampled by the original motor at the same native edge. `accept_pulse_o`/`reject_pulse_o` are registered observations, **not** commands for a second motor. `reject_reason_o` retains the original4-bit gate meanings. Map failures and full-tuple/numeric/eligibility failures enter result-invalid (9); fresh=false uses not-fresh (10), unless an earlier original priority applies. Complete map/context transitions suppress submission (STOP reason2), disarm and require a later strobe-low edge; mechanical bounds changes also use the original config transition. Expose map_valid/identity_match and original qualifiers beside the reason to explain provenance. `first_fault_o` preserves the earliest sampled fault(1), submitted abort(2), or submitted numeric-invalid(3), in that simultaneous priority, until cold reset. It is a local diagnostic audit, not a replacement for existing source/manager errors or an actuator fault classifier. Other reject reasons remain in the original registered rejection interface.

## Independent output gate; public STOP is NOT selected

**Old STOP intentionally retained PWM hold.** This increment does not alter that source or call it a historical failure. `command_stop_i` blocks new commands; `output_revoke_i` separately closes physical output. A must select the public STOP wiring: S1 connects STOP also to revoke (finish already high pulse then close); S2 retains hold on STOP and uses a separate explicit output-disable. No default S1/S2 is installed, and no automatically installing top patch is supplied pending that choice. Disable/fault/invalid mechanical approval/session/config change revoke output independently. A numeric-invalid or stale submission does not retroactively cancel a previous accepted command; lifetime/fault authority must assert the appropriate explicit input.

The guard samples the motor PWM and translates both edges by one native cycle in stable open operation, preserving pulse width. On revocation at an edge: if the **physical output was already high**, it may finish following the sampled raw high; when sampled raw goes low the output closes. If physical output was low, no new physical rising edge occurs, including a concurrent raw rise. Cold reset immediately drives low and may truncate a high pulse. No combinational AND of PWM and STOP is used.

After closure, permission alone cannot replay the old motor target. The first newly accepted command while permission is valid and not draining starts re-arm. The first subsequent sampled raw rising edge is discarded; the second opens output. This conservatively skips the old active pulse even if that command coincides with a motor boundary. With stable authorization, added startup is one-to-two raw20ms periods from that first command plus observation quantization; this is not an acoustic/hardware service budget. Later accepted commands during the same pending authorization update the original motor normally without restarting the boundary wait, including when a later command coincides with a counted raw rise. Thus frequent valid updates cannot starve opening. Reset/revoke/permission loss or the slice's config/context revocation clear the pending wait and require a new fresh command. A command during drain can reach the motor but does not re-arm the guard; submit a later fresh command after drain completes. `output_open_o`, `output_draining_o`, `awaiting_command_o`, raw_pwm and physical pwm distinguish this. Logical low/servo_enable0 never proves mechanical stationary, holding torque, safe loss-of-power or arrival.
