# Private caller interface and edges

This records the concrete implementation of frozen CALLER-1.0 A1..A9 plus CALLER-1.0-R3 reset timing. These are unsigned packed internal vectors, with field order from most significant to least significant bit. The status/valid bits are part of the vector and must not be inferred from numeric contents. No CPU byte order or public ABI is declared. Raw A fields and B read/status meanings retain their original contracts.

Context is 165 bits: `{status[1:0], boot_valid, boot[63:0], epoch_valid, epoch[63:0], sid_valid, sid[31:0]}`. `status=0` UNBOUND, `status=1` DECLARED; 2/3 are never produced. `status[164:163]`, boot_valid[162], boot[161:98], epoch_valid[97], epoch[96:33], sid_valid[32], sid[31:0]. Missing-valid requests preserve each raw field, with status zero. Equality on a live reader request includes the complete vector. Production identity is not proven by this status.

SOURCE is 1056 bits including revision64. Order: `{revision64, context165, source_status32, first_observation_valid1, first_mask5, accumulated_mask5, first_source32, first_sid_valid1, first_sid32, native_valid1, native_fault148, cancel1, first_error_valid1, first_error_code8, first_row432, token64, generation64}`. SOURCE mirror tracks observed changes, preserving the A observer's first tuple and accumulated masks. The front is immutable until ACK. Acknowledging an older front records that exact version; reset requires saved revision equals current revision and current image equals the mirror. Revisions advance before a changed image is stored; exhaustion blocks affected recovery without wrapping.

RETIRE is 1184 bits: `{old_context165, old_generation64, audit_token64, audit_count11, audit_first432, audit_bad_valid1, audit_bad432, audit_error4, audit_revoked1, audit_reason8, actual_retire_op2}`. Only the actual B audit handshake fills this record, after the checked registered command response. Audit token/op/first-row/context are checked against the retained old binding. The front cannot be overwritten before ACK. EMPTY WARM_RESET0 produces no RETIRE record and requires no invented active audit.

ISOLATION is 1081 bits including revision64: `{revision64, old_context165, held_m_valid1, raw_m432, held_e_valid1, raw_e416, m_accepted1, e_accepted1}`. The accepted bits are both zero. Invalid raw fields are canonical zero in this record; their valid flags remain explicit. Every prepare creates an explicit observation, including an empty image. Newly appearing held m/e updates the mirror and needs a new ACK. Once a held offer was observed, disappearance/change before the reset boundary is a SOURCE_HOLD protocol error. Reset requires the current held image equals the latest saved mirror. A reset deliberately invalidates the saved held offer; it never claims a prior m/e handshake.

Native fault148 keeps `{latched1, code8, parent8, sid32, source_status32, sid_valid1, id_valid1, id64, after_terminal1}`; latched[147], code[146:139], parent[138:131], sid[130:99], source[98:67], sid_valid[66], id_valid[65], id[64:1], after_terminal[0]. `native_valid` is the observer's first-copy-valid, separate from latched. Mask bits are original A private SOURCE_SYNC0, SOURCE_FULL1, PUBLISHED_FAULT2, UNEXPECTED_CLOSE3, CONTROLLED_RESET4. No translation into caller reason or C diag_fault occurs.

Raw m432 is `{pcm128,id64,flags4,sid32,frame32,interval32,sample_index10,first_id64,last_id64,reset_before1,last1}`. Raw e416 is `{code8,parent8,source_status32,source_drained1,sid32,id64,prev_id64,id_valid1,prev_id_valid1,raw_flags32,source_flags8,unused_tail11,interval32,packet32,word11,packet_words11,tdata32,tkeep4,tlast1,drop_buffered8,drop_verified8,framer_code3,framer_error_tail11,stop_truncated1}`. Entry preserves original A typed names and original B concatenations.

`rd_rsp_origin=0` denotes B, `1` LOCAL_STALE. Status 0=READ_OK, 1=READ_STALE, 2=READ_REVOKED retains B semantics. LOCAL_STALE has status1/payload0 and carries the original requested token/index/generation/context. At most one request is outstanding across both origins; ACK cannot enable another request on that edge. Prepare acceptance and a latched retirement phase backpressure all new requests, including LOCAL_STALE, while existing responses continue to ACK. Thus no new local response can be accepted after a retirement command has been formed. A matching real descriptor ACK sets lease. Matching close requires no-future-access1; it prohibits later B access for that tuple, while already accepted responses complete normally. New close acceptance also blocks current new qualification. Requests that miss a binding/lease/tuple or target a closed reader never drive B rd_valid.

Lifecycle codes: IDLE0, RUN1, PREPARING2, WAIT_RETIRE3, WAIT_SAVES4, RESET_RECOVERY5, WAIT_CLEAR6, BLOCKED7. Prepare is accepted in RUN/IDLE, retaining any already progressing normal retirement. Its actual acceptance gates both A m/e ready and B m/e valid before E and triggers observer prepare. PREPARING moves to WAIT_RETIRE on a later edge. REVOKE precedes cancelled active retirement. Historical descriptors still need ACK/lease/close. Normal complete leased windows use RELEASE; partial/quarantined unleased windows use WARM_RESET; EMPTY uses WARM_RESET0. Every retirement phase gates both directions of m/e. A normal retired window can resume the same A active session only after its real audit and save obligations close. Cancellation never clears on command success.

WAIT_SAVES admits reset request only after checked retirement, empty B slot/desc/lease/read/control obligations, actual audit saved/ACKed where required, A audit_capture_ready, latest SOURCE/ISOLATION ACK and image equality, and no hard error. P accepts the request with slice high and enters RESET_RECOVERY. H is the following actual negedge: slice is still high while all closure and current m/e/latest ACK conditions are checked. A P-produced new m/e offer rejects H unless acknowledged in the exact saved image. H authorizes a candidate only on equality and captures the candidate cut below. The continuous H→R guard compares full raw SOURCE32, native valid/valid fault148 and m valid/valid payload against that immutable cut. Any change, including frontend-ready/warm-only SOURCE32, withdraws permission. e/session/closing/source_run/observer facts never enter this guard. Slice is low only for a live candidate with this guard true. R, the following posedge, records actual execution if A samples low, or aborts and returns to WAIT_SAVES/fresh request. Subcycle permission withdrawal is not synchronous reset execution. Actual post-R changes do not create an abort: the pending request is cleared at R. Candidate-authorized e hiding never updates the isolation mirror or creates a false SOURCE_HOLD error; abort restores the original e visibility, and genuine late facts are saved before a fresh request. The original saved isolation record survives successful R unchanged.

Old B terminal may remain in its dedicated immutable B register, with context/binding/token/generation latched only at the original e handshake; it survives clear/start without relabeling. Throughout P/H/R all A m/e ready and B m/e valid are zero. B cold reset is unaffected. On successful R the caller enters WAIT_CLEAR. Actual clear is no earlier than a subsequent slice-running posedge, requires real observer clear readiness and settled B/read/save state, and excludes start/reset. It clears only recoverable current control/observer state after preservation. Allocators and terminal history survive. No start is allowed on the clear edge.

R3 diagnostics distinguish `reset_request_accepted` (actual P valid/ready), `reset_candidate_authorized` (H-authorized pending candidate, irrespective of a later guard withdrawal), `reset_guard_matches` (current independent guard with pending candidate), `reset_abort` (registered pulse after rejected R), and `slice_reset_executed` (registered pulse after actual R). Abort/executed pulses clear on the next posedge. `reset_candidate_cut[1323:0]` is an immutable 1324-bit H record: `{old_context165, raw_source32, native_valid1, valid_native_fault148, m_valid1, valid_m432, e_valid1, valid_e416, source_saved_revision64, isolation_saved_revision64}`. Invalid payloads are canonical zero. The cut is retained after R until the next authorized H or cold initialization; e/content/context are evidence fields, not continuous guard inputs. A/B accurate entry properties support this boundary; arbitrary core producer timing, external frontend-ready feedback from slice reset and all half-cycle/guard physical timing remain UNVERIFIED. No new H-stable-input assumption exists.

Stable command tuple is `{op2,token64,reason8}`. Ops RELEASE0/REVOKE1/WARM_RESET2. The caller registers one offer, waits for actual fire, then ACKs the registered B response and checks echo/status; no next offer on response ACK E. OK retires only after checking response. BUSY2/AUDIT_FULL3 retain logical retirement and retry on a later edge after real blocking obligations clear; actual audits are saved before retry. STALE1 is not successful and is a hard conflict in this implementation: its serialized transaction state generates neither a no-token REVOKE nor a previously successful-retirement stale race. BAD_OP4/reserved statuses and any non-OK REVOKE are hard errors. cmd_fire is transport only. Registered diagnostics expose offer/wait/fire/response/status; no external command master exists.

Caller reason namespace: A1 SOURCE_CANCEL, A2 CONTROLLED_PREPARE, A3 IDENTITY_CONFLICT, A4 CALLER_PROTOCOL_ERROR, A5 INPUT_TRANSPORT_ERROR. First cancellation reason is retained independently of later A mask/native facts. First-error codes: 1 IDENTITY_MISSING, 2 SID_CONFLICT, 3 BINDING_CONFLICT, 4 COMMAND_ECHO, 5 COMMAND_STATUS, 6 AUDIT_CONFLICT, 7 SOURCE_REVISION_LIMIT, 8 ISOLATION_REVISION_LIMIT, 9 SOURCE_HOLD, 10 INPUT_ERROR, 11 READ_RESPONSE_ERROR. Codes 1/2/10 retain cancellation and permit the explicit prepare recovery. Codes 3..9/11 block the affected recovery in BLOCKED; cold invalidation remains an external unverified prerequisite. First error is not overwritten by cancellation; SOURCE carries the first error before clear. Generation exhaustion uses its explicit diagnostic and blocks further allocation, allowing the last allocated identity to finish.

Priority is cold initialization; pre-edge cancel/prepare/identity/qualified close blocking; reset/clear gates; historical ACKs; stable command fire and registered response; original legal source accepts/first-row generation; cumulative late facts. A/B original module cycles do not change. This caller adds the explicitly frozen following-edge binding, serial read tagging, finite save transactions and recovery phases. The R3 Cycle Contract Delta is request P, authorization H, actual reset/abort R, then later clear/start. m can accept one row/clock while forwarding; no finite retirement/reset latency bound exists without reader/sink progress. CC01..CC15 and the mandatory R3 targeted P-after-offer/H→R-change/no-change/abort/history/clear-start checks remain NOT_RUN in this author batch, alongside actual clock/reset/CDC/RDC/STA and algorithm/production claims.
